Проведи аудит: $ARGUMENTS (если область не указана — весь проект).

Это отдельная сознательная операция, а не фон при выполнении задач.
Задача — найти реальные проблемы, а не выдать список общих улучшений.

Проверь:
1. **Корректность** — ошибки логики, необработанные ветки, гонки, утечки ресурсов.
2. **Безопасность** — валидация входных данных, инъекции, секреты в коде, права доступа.
3. **Дублирование** — параллельные реализации одного и того же, копипаста.
4. **Соответствие архитектуре** — нарушения границ из `docs/ARCHITECTURE.md` и принятых ADR.
5. **Кроссплатформенность** — Windows dev → Ubuntu prod: пути, регистр имён файлов, переводы строк.
6. **Обработка ошибок** — проглоченные исключения, ошибки без контекста, отсутствие таймаутов и ретраев.
7. **Тесты** — непокрытые критичные пути.

Формат ответа:
- Сгруппировать по severity: **Критично / Важно / Стоит поправить**.
- Каждый пункт: `файл:строка` → в чём проблема → чем это грозит → как чинить.
- Только то, что подтверждено чтением кода. Догадки помечать явно как гипотезы.
- Ничего не чинить без подтверждения. Сначала отчёт.
- В конце — 3 пункта, которые дадут наибольший эффект.

Найденное, что не чиним сейчас, добавь в `TASKS.md`.
