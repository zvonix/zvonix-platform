# Доменная модель Zvonix

<!-- Заполняется ДО первой миграции. Термины совпадают с GLOSSARY.md слово в слово. -->

## Что делает система

Zvonix — площадка терминации исходящих голосовых вызовов через GSM-шлюзы.
**Клиенты** (службы такси) совершают исходящие звонки; вызов маршрутизируется на
GSM-шлюз одного из **партнёров** (физлиц с SIM-картами и GOIP-оборудованием),
который его терминирует. С баланса клиента списывается стоимость звонка, партнёр
получает свою долю, платформа удерживает комиссию.

Администратор задаёт коридор цен по направлениям, комиссию платформы, лимиты
и правила маршрутизации. Партнёр назначает свою цену внутри коридора.
Разговоры записываются и доступны обеим сторонам.

## Роли

| Роль      | Кто это | Что делает |
|-----------|---------|------------|
| `admin`   | Владелец платформы | Коридоры цен, комиссия, лимиты, узлы АТС, модерация партнёров, разбор споров |
| `partner` | Физлицо с SIM и GOIP | Регистрирует шлюзы и SIM, ставит цену в коридоре, получает выплаты |
| `client`  | Служба такси | Создаёт каналы, звонит, пополняет баланс, слушает записи |
| `support` | Сотрудник поддержки | Только чтение + разбор обращений, без доступа к деньгам |

## Связи

| От | К | Тип | При удалении родителя |
|----|---|-----|------------------------|
| `Client` | `Channel` | 1:N | Запрет, если есть CDR; иначе архивирование |
| `Partner` | `Gateway` | 1:N | Запрет, если есть незавершённые расчёты |
| `Gateway` | `GatewayPort` | 1:N | Каскад |
| `GatewayPort` | `SimCard` | 1:1 (текущая) | Обнуление — SIM переживает порт |
| `Partner` | `SimCard` | 1:N | Запрет |
| `Channel` | `Call` | 1:N | Запрет — CDR не удаляются никогда |
| `Call` | `Cdr` | 1:1 | Запрет |
| `Cdr` | `Recording` | 1:0..1 | Каскад по истечении срока хранения |
| `Cdr` | `LedgerEntry` | 1:N | Запрет — проводки неизменяемы |
| `Node` | `Gateway` | 1:N (регистрация) | Обнуление — шлюз перерегистрируется на другой узел |

## Инварианты

- **Сумма проводок по счёту равна его балансу.** Всегда. Баланс не редактируется напрямую —
  только проводкой.
- **Проводка неизменяема.** Ошибка исправляется обратной проводкой, а не правкой.
- **Звонок не тарифицируется дважды** — идемпотентность по идентификатору CDR.
- **Баланс клиента не уходит ниже разрешённого овердрафта** — обеспечивается резервированием
  до начала звонка, а не проверкой после.
- **Цена партнёра всегда внутри действующего `PriceBand`** для направления.
  Изменение коридора не меняет задним числом уже совершённые звонки.
- **Ни одно окно `LimitPolicy` не превышено** — ни у клиента, ни у канала, ни у партнёра,
  ни у SIM.
- **Запись об операторе номера действительна ограниченный срок** (по умолчанию 30 дней,
  настраивается): абонент может перенести номер повторно. Просроченная запись обновляется
  при следующем обращении к номеру. Обращение партнёра «вызов ушёл не в мою сеть»
  отменяет запись немедленно, независимо от срока.
- **Клиент никогда не получает данных, позволяющих связаться с партнёром напрямую.**
  Партнёр виден клиенту только под псевдонимом: ни имени, ни контактов, ни реквизитов,
  ни номеров его SIM в интерфейсе, отчётах, CDR и записях. Обход платформы = потеря выручки.
- **Клиент платит только за вызовы.** Абонплаты за канал, за номер и прочих регулярных
  списаний нет. Правила тарификации задаёт партнёр в `PartnerRate`, платформа добавляет
  свою наценку сверху.
- **Одна SIM обслуживает `max_concurrent_calls` вызовов, по умолчанию 1.** Значение
  изменяется только администратором: превышение — прямой путь к блокировке SIM оператором.
- **Вызов идёт только на партнёра, покрывающего регион номера** — по его `PartnerCoverage`.
- **Вызов совершается только если оператор номера подтверждён и найдена свободная SIM
  этого же оператора.** Все партнёрские SIM работают на безлимите внутри своей сети,
  поэтому верное определение делает звонок бесплатным, а неверное — платным для партнёра.
  Промежуточного варианта нет: SIM с внесетевыми минутами в модели не существует.
  Не подтверждён оператор — вызов отклоняется (см. [ADR-0013](adr/0013-opredelenie-operatora.md)).
- **Канал с `recording_required` никогда не маршрутизируется на шлюз типа `android`** —
  на Android 10+ запись разговора недоступна (см. [ADR-0012](adr/0012-mobilnoe-prilozhenie.md)).
- **Запись принадлежит ровно одному CDR** и доступна только участникам этого звонка
  (клиент, терминировавший партнёр) и админу.
- **Цена, применённая к звонку, фиксируется в CDR** на момент звонка. Последующее изменение
  тарифов не влияет на прошлое.

## Жизненные циклы

### Call
```
created → routing → ringing → answered → completed
             ↓         ↓         
          failed    no_answer / busy / rejected / cancelled
```
Тарифицируются только `completed` (и, по настройке направления, `answered`-без-разговора нет).

### Reservation
```
held → captured   (звонок завершён, списана фактическая сумма)
  ↓
released          (звонок не состоялся или резерв истёк)
```

### SimCard
```
new → active → throttled → blocked → retired
              ↑        ↓
              └────────┘   (лимиты/ASR восстановились)
```

### Payout
```
requested → approved → sent → completed
                ↓        ↓
            rejected  failed
```

### Node
```
provisioned → installing → online → degraded → offline → decommissioned
```

## Идентификаторы

- Тип: **UUIDv7** для всех публичных сущностей.
- Обоснование: генерируются на стороне приложения (нужно для идемпотентности до записи в БД),
  не раскрывают объём бизнеса в отличие от автоинкремента, при этом монотонны по времени
  и не разрушают локальность индекса как UUIDv4.
- Исключение: `LedgerEntry` и `Cdr` дополнительно имеют монотонный числовой номер
  для человекочитаемой сверки.

## Деньги

- Хранение: целое число в **микроединицах валюты** (1 руб = 1 000 000). Плавающая точка
  запрещена везде, включая промежуточные вычисления и передачу по API.
- Округление: только в момент фиксации CDR, правило округления — часть тарифа, не кода.
- Валюта — атрибут счёта, мультивалютность заложена в схеме, но в v1 одна валюта.

## Открытые вопросы

- Юрисдикция и правовая модель работы (см. [ADR-0011](adr/0011-pravovoy-kontur.md)) — влияет
  на KYC, сроки хранения записей и возможность отключения направлений.
- Модель выплат партнёрам: самозанятые / договор ГПХ / иное — влияет на состав данных KYC
  и налоговую отчётность.
- Нужна ли поддержка входящих вызовов на номера SIM партнёров (сейчас модель только исходящая).
