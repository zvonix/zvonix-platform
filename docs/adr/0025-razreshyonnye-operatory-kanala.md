# ADR-0025: Разрешённые операторы канала — закрытый список с отдельной причиной отказа

- **Статус:** Принято
- **Дата:** 2026-09-03
- **Связано с:** [ADR-0013](0013-opredelenie-operatora.md), [ADR-0024](0024-chyornyy-spisok-nomerov.md)

## Контекст

`Channel` в [DOMAIN.md](../DOMAIN.md) описан с атрибутом «разрешённые операторы»,
а [ARCHITECTURE.md](../ARCHITECTURE.md) называет проверку «оператор разрешён каналом
клиента» среди шагов маршрутизации. Ни колонки, ни проверки не было: канал звонил
на любого оператора, для которого нашлась SIM.

Расхождение документации с кодом здесь не безобидно. Клиент, которому обещали ограничение
направлений, его не получил — и узнал бы об этом по счёту, а не по отказу.

## Решение

### 1. Список закрытый, пустой означает «все операторы»

То же правило, что у приоритетов партнёров ([ADR-0014](0014-vybor-partnera-klientom.md)),
покрытия по регионам ([ADR-0022](0022-pokrytie-regionov.md)) и коридоров цен
([ADR-0023](0023-koridory-cen.md)), и по той же причине: новый канал, не смогший позвонить
до заполнения списка, выглядел бы поломкой платформы, а не своей настройкой.

Список принадлежит каналу, а не клиенту: у одной службы такси может быть линия «звонить
куда угодно» и линия «только на четвёрку крупных». Владение проверяет служба, а не
защитник, — чужой канал отвечает `404` ([ADR-0018](0018-autentifikaciya.md)).

### 2. Сравнивается **определённый** оператор, а не префикс номера

Проверка стоит **после** `OperatorResolver` и работает с тем оператором, которого он
подтвердил. Проверять по префиксу нельзя ровно по той же причине, по которой нельзя
по нему маршрутизировать ([ADR-0013](0013-opredelenie-operatora.md)): из-за переносимости
номеров префикс называет не того оператора, и «разрешён» оказалось бы вычислено
для оператора, который номер уже не обслуживает.

Отсюда порядок: канал → чёрный список → **оператор** → разрешён ли он каналом → кандидаты.

### 3. Своя причина отказа, а не `destination_blocked`

Добавлена причина `operator_not_allowed` (SIP `403 Forbidden`).

Переиспользовать `destination_blocked` было бы дешевле на одну миграцию и неверно
по существу: это два разных разговора с клиентом. «Номер запрещён платформой» —
запрет, который клиент не снимет; «оператор не разрешён вашим каналом» — его собственная
настройка, которую он меняет сам. Свалить их в одну причину значит отправлять поддержку
разбираться туда, где разбирать нечего.

Значение добавляется к перечислению — это **дополнение** контракта узла, а не изменение:
узел на причину не переключается, он получает код SIP и пишет причину в CDR.
Так же в своё время добавлялась `node_lost`.

### 4. Клиенту открывается справочник операторов

Чтобы выбрать разрешённых операторов, клиент должен их видеть: `GET /operators` теперь
доступен и роли `client`. Ограничения [ADR-0014](0014-vybor-partnera-klientom.md) это
не нарушает — оператор связи не партнёр, и связь «оператор → партнёр» наружу не выходит
ни здесь, ни где-либо ещё.

## Последствия

- **Положительные.** Документация и код перестают расходиться: обещанное ограничение
  направлений работает. Отказ отличим от запрета платформы и от «нет SIM».
- **Отрицательные и принятая цена.** Ещё одно чтение на горячем пути — по уникальному
  индексу и только у каналов, которые список завели. Клиент, заполнивший список
  и забывший про него, получит отказы при появлении новых операторов у партнёров:
  это следствие «закрытого списка», и оно то же самое, что у приоритетов партнёров.
- **Что осталось открытым.** Интерфейса для этой настройки нет — кабинет клиента
  появится на этапе 5. Пока список задаётся по API.
