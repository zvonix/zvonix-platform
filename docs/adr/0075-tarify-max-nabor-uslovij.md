# ADR-0075: Тарифы MAX — именованный набор условий, назначение аккаунту, умолчание партнёра

- **Статус:** Принято — 2026-10-07, решение владельца: «создаём тариф и потом в определённый аккаунт назначаем тариф +
  тариф по умолчанию»; «делай что рекомендуешь» (один тариф = цена + лимиты; сначала MAX, звонки позже)
- **Дата:** 2026-10-07
- **Связано с:** [ADR-0071](0071-soobscheniya-max.md) (цена и лимиты на аккаунте), [ADR-0056](0056-tarify-partnyora.md)
  (тарифы звонков — образец), [ADR-0005](0005-migracii.md), [ADR-0016](0016-soglasheniya-shemy-bd.md)

## Контекст

У звонков условия устроены так: **именованный тариф** (набор цен), он **назначается** шлюзу или SIM, у партнёра есть
**тариф по умолчанию** (ADR-0056). У сообщений MAX цена и лимиты вписаны отдельными полями в каждый аккаунт: ни имён, ни
назначения, ни умолчания. Три разных схемы (звонки, лимиты звонков, MAX) путают: владелец не находит, где что задаётся,
и просит одну логику везде.

## Решение

1. **Тариф MAX** — таблица `messenger_tariffs`: партнёр, имя (уникально у партнёра без учёта регистра), **цена за
   сообщение**, **лимиты в минуту и в сутки** (пусто — без ограничения), признак «по умолчанию» (один на партнёра).
   Один тариф — и цена, и лимиты: так их не нужно собирать из двух наборов, а аккаунт с ценой, но без лимитов,
   невозможен по случайности.
2. **Назначение.** `messenger_accounts.tariff_id` (необязательное). Условия аккаунта: **свой тариф → тариф по
   умолчанию партнёра → нет** (аккаунт сообщений не принимает: нет цены). Тот же порядок «своё → умолчание», что у SIM.
3. **Действующие условия хранятся на аккаунте** (`price`, `limit_per_minute`, `limit_per_day` — как и раньше) и
   пересчитываются **одной функцией** `recomputeTerms(партнёр)` в той же транзакции, что и любое изменение тарифа,
   назначения, умолчания или заведение аккаунта. Так выбор аккаунта под сообщение (горячий путь) и сверка лимитов
   не получают соединений и не меняются. Поля аккаунта — **производные**, прямой записи в них нет.
4. **Правка тарифа действует на аккаунты сразу**, но уже принятые сообщения не затрагивает: цена фиксируется на
   сообщении при приёме (ADR-0071).
5. **Удаление тарифа** — только неиспользуемого: нет аккаунтов, назначенных на него, и он не по умолчанию. Тариф по
   умолчанию переназначается (становится умолчанием другой), а не удаляется.
6. **Миграция данных.** Для каждого партнёра различные сочетания (цена, лимиты) у его живых аккаунтов становятся
   тарифами: самый частый — «Основной» и по умолчанию, остальные — «Тариф 2», «Тариф 3»…; аккаунты назначаются на них.
   Старые аккаунты без цены остаются без назначения и **после этой миграции получают условия по умолчанию**, если
   у партнёра он появился (это и есть смысл умолчания). Старых полей не удаляем (двухшаговое правило ADR-0005).
7. **Кабинеты.** «Мои тарифы» партнёра → вкладка «Сообщения MAX»: таблица тарифов (имя, цена, лимиты, сколько
   аккаунтов, «по умолчанию»), «Создать тариф», правка, «Сделать по умолчанию», удаление. «Аккаунты MAX»: у каждого
   аккаунта колонка «Тариф» с выбором (по умолчанию / конкретный) и итоговыми ценой и лимитами; поля цены и лимитов из
   правки аккаунта уходят. «Лимиты» → вкладка «Сообщения MAX» — только просмотр действующих лимитов по аккаунтам со ссылкой
   на тарифы. Администратор видит действующие условия по аккаунтам (как сейчас), правка — за партнёром.
8. **Что не меняется:** наценка площадки (ADR-0073), выбор аккаунта по цене (ADR-0071, п. 8), SMPP, деньги.

## Что дальше (не в этом ADR)

- Тот же порядок для **лимитов звонков** («профили лимитов» вместо трёх областей правил) и единый вид «Тарифы» и
  «Лимиты» во всех кабинетах — отдельным решением после разбора всех разделов (таблица расхождений — в TASKS.md).
- Назначение тарифа **клиенту** (цена для клиента) — тарифы клиента остаются наценкой площадки (ADR-0073).

## Последствия

- Партнёру понятно, где менять цену: в тарифе, а не в каждом аккаунте; новый аккаунт сразу получает условия.
- Цена за сообщение и лимиты у аккаунта меняются только через тариф: один путь вместо двух.
- Расхождение производных полей с тарифами исключено одной функцией пересчёта и тестом на неё; при подозрении
  функцию можно запустить заново для партнёра.
