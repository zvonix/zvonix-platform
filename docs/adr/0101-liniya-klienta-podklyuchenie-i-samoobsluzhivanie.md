# ADR-0101: Линия клиента — подключена ли она, выключение и удаление клиентом, комментарий, предел одновременных

- **Статус:** Принято — 2026-10-28; владелец: «нет настроек подключения», «номер SIM, с которой ушёл вызов — вводит
  в заблуждение», «полноценно сделай этот раздел», «показывать, есть подключение или нет, а не всегда; если не подключено —
  так и писать», «ещё добавь поле комментарий», «может не закрыть линию, а удалить?»; на развилки — опрос узлов,
  клиент и администратор видят комментарий, клиент сам выключает и удаляет
- **Дата:** 2026-10-28
- **Развивает:** [ADR-0058](0058-klient-sam-poluchaet-liniyu.md)
- **Пересматривает:** [ADR-0058](0058-klient-sam-poluchaet-liniyu.md), п. 5 — «клиент не меняет состояние»

## Контекст

Линия (канал) — вход SIP, через который программа такси или АТС клиента звонит через площадку. Страница «Линии» показывала
только название, состояние, «номер для показа» и «запись». Главного вопроса при настройке — «почему не звонит: подключилась
ли программа?» — она не решала. Сервер и имя показывались один раз при выдаче, хотя секрет из них только пароль.
Выключить, переименовать и удалить линию клиент не мог.

«Номер для показа» вводил в заблуждение: пусто — значит «номер той SIM, через которую прошёл вызов», а клиент читал это
как один номер. Через SIM свой номер не показать вовсе: его подставляет сеть оператора.

Отметка «на связи», какая уже есть у шлюзов партнёров, здесь не годится: это факт запроса учётной записи узлом, и программа
со старым паролем тоже выглядит подключённой (TASKS.md, 4.28). Для клиента это ровно случай «почему не звонит».

## Решения

1. **«Подключена» — по регистрациям на узле, опросом раз в минуту.** Воркер (`channels.registrations`) отдаёт каждому
   не списанному узлу с ESL команду `show registrations as json` и записывает у линий, чьё имя есть в ответе: когда видели,
   до какого момента действует регистрация, адрес программы, узел. Регистрация есть только после верного пароля — старый
   пароль подключённой линию не сделает. Подключена — регистрация действует и видели её не раньше трёх минут назад: узел
   замолчал — линия честно «не подключена». Мгновенная подписка на события ESL отклонена: отдельная долгоживущая служба
   ради задержки в минуту.
2. **Программа, которая звонит без регистрации,** — «не подключена», но рядом время последнего вызова: иначе работающая
   линия выглядела бы сломанной.
3. **Сменился пароль, линию выключили или удалили — регистрация на узле сбрасывается** (`sofia profile … flush_inbound_reg`),
   и отметка в базе стирается. Иначе программа со старым паролем числилась бы подключённой до конца срока регистрации.
   Узел не ответил — запись в журнал предупреждений, действие клиента не отменяется: регистрация всё равно истечёт.
4. **Клиент сам выключает, включает и удаляет линию.** Кто выключил — `suspended_by`: `client` или `admin`, как у шлюза
   ([ADR-0047](0047-kto-vyklyuchil-shlyuz.md)). Выключенную администратором клиент не включает и не удаляет: «удалил —
   получил новую» обошло бы решение площадки. Удаление — состояние `closed`, необратимое: строку стереть нельзя, на неё
   ссылаются вызовы и проводки, и история в «Вызовах» сохраняется с названием линии. Удалённая линия не показывается клиенту
   и не считается в предел пяти линий; её вход не работает.
5. **Комментарий** — до 500 знаков, пишет клиент, видит и администратор (карточка клиента). Партнёр не видит никогда.
6. **Предел одновременных разговоров линии** — `max_concurrent_calls`, пусто — без предела, иначе 1–1000. Проверяется
   той же транзакцией, что занимает SIM: линия запирается, считаются её открытые вызовы. Превышение — `limit_exceeded`,
   уже видимая клиенту причина: новая причина ничего не добавила бы к «упёрлись в предел».
7. **Данные подключения** — на странице линии, вкладка «Подключение»: сервер, порт, имя, кодеки, формат номера. Пароль
   не показывается никогда (в базе хеш), только «Новый пароль».
8. **«Номер для показа» из кабинета клиента убран.** Поле `caller_id` в ответе API остаётся: клиентский контракт
   ([ADR-0044](0044-klientskiy-api.md)) поля не теряет.
9. **Сводка линии** — из готового разреза отчётов по линиям (`GET /client/reports/breakdown?by=channel`, сегодня и 7 дней,
   по поясу браузера, как «Сводка»): вызовы, отвеченные, минуты, расход. Отдельного обработчика не заводится. В списке
   линий к ним добавлены «разговоров сейчас» и «последний вызов».

## Последствия

- Миграция: у `channels` — `comment`, `max_concurrent_calls`, `suspended_by`, `registration_seen_at`,
  `registration_expires_at`, `registration_address`, `registration_node_id`; состояние `closed`. Существующие выключенные
  линии получают `suspended_by = admin` — их выключала площадка.
- Опрос годится и для шлюзов партнёров (4.28) — отдельной задачей.
- Ответ `show registrations as json` на живом узле не проверен: формат взят из исходников FreeSWITCH. Первая выкладка
  проверяется навыком `node-live`.
