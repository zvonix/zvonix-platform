# ADR-0056: Тарифы партнёра — именованные наборы цен; куда звонит SIM, решает её тариф

- **Статус:** Принято — 2026-09-29, решение владельца («делай что рекомендуешь»;
  уточнения 2026-09-25 — ниже, в «Контексте»)
- **Дата:** 2026-09-29
- **Связано с:** [ADR-0013](0013-opredelenie-operatora.md) (оператор номера),
  [ADR-0023](0023-koridory-cen.md) (коридоры цен — пересматривается),
  [ADR-0040](0040-poryadok-terminacii-predlozhenie-i-cena.md) (цена решает порядок),
  [ADR-0010](0010-model-billinga.md) (биллинг), [ADR-0035](0035-operator-vladeet-svoey-setyu.md)

## Контекст

Сейчас цена партнёра — набор строк `partner_rates` «оператор × регион × способ
терминации» без имени, одна на всего партнёра. SIM звонит **только на номера своего
оператора** (`findSimCandidates`: `sim_cards.operator_id = оператор номера`), а вызов
с неподтверждённым оператором не совершается вообще: проект исходил из того, что у всех
партнёров «безлимит внутри своей сети».

Владелец (2026-09-25):
- «карта звонит бесплатно только внутри своей сети — откуда ты это знаешь? не нужно так
  ограничивать»; «партнёр сам выбирает, на каких операторов можно звонить — на всех
  или на выбранных»; «какая разница какой оператор — звонки всё равно должны проходить»;
- «партнёр сам задаёт, по какой цене готов продавать; нужны тарифы — тариф по умолчанию
  и другие; тариф выбирается для всего GOIP и меняется у каждой SIM»;
- коридор цен — «сделать возможность вообще не задавать или отключить»;
- цена, изменённая в тарифе, — «делай как рекомендуешь»: действует сразу, прошлые звонки
  не пересчитываются.

## Решение

### 1. Тариф — именованный набор цен партнёра

Новая таблица `partner_tariffs`: `partner_id`, `name`, `is_default`. Имя уникально
у партнёра (без учёта регистра), тариф по умолчанию у партнёра **ровно один**
(частичный уникальный индекс). Строки `partner_rates` получают `tariff_id`: цена
принадлежит тарифу, а не партнёру напрямую. `partner_id` у цены остаётся — по нему
идут блокировки, журнал и нынешние выборки.

Существующие цены каждого партнёра переезжают в его тариф «Основной», он же
по умолчанию. Партнёр без цен тоже получает пустой «Основной»: тариф по умолчанию есть
у каждого, и SIM всегда есть к чему привязать.

### 2. Цена «на все операторы» плюс исключения

`partner_rates.operator_id` становится необязательным: пусто — **цена на все
операторы** этого тарифа. Какая строка тарифа действует для номера, решает старшинство:

1. оператор номера и его регион;
2. оператор номера, без региона;
3. все операторы, регион номера;
4. все операторы, без региона.

Внутри уровня — наибольший `effective_from <= момент`. Так партнёр задаёт одну цену
«на всех» и по нужде — исключение для отдельного оператора.

### 3. Тариф выбирается у шлюза и меняется у SIM

`gateways.tariff_id` и `sim_cards.tariff_id`, оба необязательны. Действующий тариф SIM:
**свой → тариф шлюза, в порту которого она стоит → тариф партнёра по умолчанию.**
Транк (`sip_trunk`) — тариф своего шлюза, иначе по умолчанию. Тариф чужого партнёра
назначить нельзя: проверяет сервис, в той же транзакции.

### 4. Куда звонит SIM, решает её тариф

Условие «оператор SIM равен оператору номера» из отбора кандидатов **снимается**.
SIM — кандидат на номер, если в её действующем тарифе есть цена для этого номера
(правило ADR-0040 «нет цены — нет кандидата» уже такое). Отдельного «списка
операторов назначения» у SIM нет: хочешь только своих — задай цены только для них;
хочешь всех — цена «на все операторы».

Карты и шлюзы существующих партнёров после миграции звонят по ценам их «Основного»
тарифа. **Это расширение**: карта оператора А начнёт звонить на номера оператора Б,
если у партнёра есть цена для Б. Владелец согласен: «звонки всё равно должны проходить».

### 5. Оператор номера — подтверждённый, иначе владелец диапазона

Вызов больше не отклоняется только за то, что оператор не подтверждён. Цена ищется
по подтверждённому оператору номера (`lookup`, `manual`), а если подтверждения нет —
по владельцу диапазона из плана нумерации (`numbering_plan`). Оператора нет вовсе
(номер вне плана) — отказ `operator_unconfirmed`, как сейчас: номер, которого нет
в плане нумерации, почти всегда набран с ошибкой, а вызов и отчёты клиента держатся
на операторе.

В CDR и журнале вызова остаётся, по какому оператору взята цена и подтверждён ли он.

### 6. Коридор можно не задавать и можно отключить

- **Направление без коридора партнёру открыто** (прежде — закрыто). Коридор — рамка,
  которую администратор ставит там, где хочет, а не пропуск.
- **Настройка площадки `pricing.price_bands_enabled`** (по умолчанию — включена):
  выключена — коридоры не проверяются вовсе, ни при назначении цены, ни в отчёте
  «вне коридора». Сами коридоры не удаляются: включил снова — действуют.
- Цена «на все операторы» при включённых коридорах обязана уложиться **в каждый**
  действующий коридор без региона и с регионом цены: иначе через неё обходился бы
  коридор отдельного оператора.
- Остаётся прежнее: проверка и запись — одна транзакция с запиранием направлений,
  момент начала у партнёра не принимается, сравнивается стоимость эталонного вызова.

### 7. Изменение цены действует сразу; прошлое не пересчитывается

Партнёр меняет цену — новая строка с `effective_from = сейчас`, как и сейчас; все SIM
с этим тарифом звонят по ней со следующего вызова. Чтобы **идущий** вызов и его CDR
не зависели от смены тарифа у SIM посреди разговора, вызов запоминает строку цены
при маршрутизации: `calls.partner_rate_id`. CDR тарифицируется по ней; у вызовов,
маршрутизированных до этой версии, — по-прежнему, поиском на момент начала.

### 8. Кабинет

- «Мои тарифы» (бывшие «Мои цены»): список тарифов, у каждого — цены; создать,
  переименовать, сделать тарифом по умолчанию, удалить неиспользуемый. Цена
  «на все операторы» — первая строка тарифа.
- Страница шлюза — выбор тарифа для всех его SIM; строка порта — тариф карты
  («как у шлюза» или свой).
- Администратор видит и правит то же у партнёра; действия журналируются.

## Последствия

- Правила CLAUDE.md меняются: «Вызов с неподтверждённым оператором не совершается
  вообще», «Коридор — единственное ограничение… направление без коридора партнёру
  закрыто» — пересматриваются этим ADR. DOMAIN.md — сущность `PartnerTariff`,
  инварианты цены.
- Миграция только добавляет: таблица, три необязательные колонки, перенос цен
  в «Основной». `partner_rates.tariff_id` пока допускает пусто — старый код в окне
  выкладки пишет цены без тарифа; `NOT NULL` — следующей миграцией (TASKS.md).
  Цена без тарифа читается как цена тарифа по умолчанию.
- `operator_id` у цены допускает пусто — снятие `NOT NULL` совместимо со старым кодом.
- Порядок кандидатов (ADR-0040) не меняется: приоритет → цена → давность → номер SIM;
  цена теперь своя у каждой SIM, а не у партнёра.
- Лимиты партнёра (4.30) — отдельное решение.

## Отклонённые варианты

- **Список операторов назначения у SIM** рядом с ценами. Два места, решающих одно
  и то же, расходятся: оператор в списке без цены — всё равно нет звонка.
- **Тариф только у шлюза.** Владелец прямо просил менять у каждой SIM.
- **Пересчёт прошлых звонков** по новой цене — противоречит неизменности проводок
  (ADR-0010, ADR-0034).
