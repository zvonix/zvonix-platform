# ADR-0092: Требования клиента к аккаунтам MAX и «СТОП» — снова решение партнёра

- **Статус:** Принято — 2026-10-22; владелец: «СТОП должен сам партнёр включить или выключить, а клиент должен видеть, у какого
  партнёра и в каком аккаунте»; «если партнёров и аккаунтов будет много и часть клиенту не подойдёт — как удобно выбирать?» —
  ответ «да» на предложение «требования + таблица аккаунтов»
- **Дата:** 2026-10-22
- **Пересматривает:** [ADR-0090](0090-dengi-admina-i-limity-akkaunta.md), п. 2 («СТОП» без галочки)
- **Связано с:** [ADR-0081](0081-prioritety-partnyorov-u-klienta.md) (приоритеты), [ADR-0014](0014-vybor-partnera-klientom.md)
  (клиент не видит партнёра), [ADR-0079](0079-raspredelenie-soobscheniy-i-zdorove-akkauntov.md) (выбор аккаунта)

## Контекст

Партнёров и аккаунтов MAX может быть сотни, условия у них разные: «СТОП» в сообщениях, рекомендованная работа, цена, возраст
аккаунта. Расставлять каждый аккаунт руками клиент не будет; ему нужно сказать «какие мне подходят», а площадке — соблюдать это
при каждом выборе.

## Решения

1. **«СТОП» в сообщениях — снова галочка партнёра** у каждого аккаунта (`messenger_accounts.stop_line`, по умолчанию включена;
   `PATCH /partner/messenger/accounts/:id { stopLine }`). Колонка не удалялась, данные прежние.
2. **Требования клиента** — одна запись на клиента (`client_message_requirements`), действуют на каждый выбор аккаунта: при приёме,
   при перевыборе соседа при отправке и при расчёте цены:
   - «СТОП»: не важно / только со «СТОП» / только без;
   - только с рекомендованной работой;
   - цена для клиента не дороже N ₽ (с наценкой; переводится в предел цены партнёра точным поиском — наценка монотонна);
   - аккаунт работает не меньше N суток (по дате заведения).
   Доля доставленных как требование — следующим шагом: нужна статистика по аккаунтам с порогом выборки.
3. **Ручное отключение аккаунта** клиентом (`client_account_exclusions`): аккаунт не берётся для этого клиента.
4. **Таблица «Аккаунты MAX» у клиента** (`GET /client/messages/accounts`): псевдоним партнёра и «аккаунт N» (порядковый номер
   у партнёра по дате заведения — не номер телефона и не название партнёра, ADR-0014), цена для клиента, «СТОП», рекомендованная
   работа, возраст, подходит ли и почему нет, отключён ли вручную. Только рабочие аккаунты подтверждённых партнёров.
5. **Порядок выбора:** требования и ручные отключения → цифры партнёров (ADR-0081) → самая дешёвая цена → режим партнёра.
   Никто не подходит под требования, а без них подошёл бы — приём отвечает `409` «Под ваши требования к аккаунтам сейчас никто
   не подходит», а не «повторите позже».
6. **Журнал:** изменение требований — `client_message_requirements.set`, отключение — `client_account_exclusion.set`.

## Последствия

- Выбор аккаунта получает до четырёх условий в том же запросе кандидатов и одно чтение требований клиента; партнёрский путь без
  клиента (перевыбор соседа) получает идентификатор клиента явно.
- Клиент видит, сколько аккаунтов ему доступно, и может сам сузить круг; партнёр видит только своё.
