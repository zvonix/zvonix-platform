# ADR-0091: Блокировка бота — настройкой; «только первое» — по пути отправки

- **Статус:** Принято — 2026-10-22; владелец: «блокировка бота = не писать — сделай настройку в админке, по стандарту блок бота не
  является блоком аккаунтов партнёров»; «первое сообщение в боте должно быть первым, не важно, сколько ушло через аккаунты»
- **Дата:** 2026-10-22
- **Связано с:** [ADR-0088](0088-otchety-i-zashchita-akkauntov-max.md) («СТОП», «Не писать»),
  [ADR-0087](0087-konstruktor-soobshcheniya.md) (конструктор сообщения), [ADR-0077](0077-bot-max-vtoroy-kanal.md) (бот)

## Решения

1. **Остановка или блокировка бота.** Признаки: событие MAX `bot_stopped` или `dialog_removed`
   (https://dev.max.ru/docs-api/objects/Update) и отказ платформы при отправке подписчику. Подписчик всегда помечается
   остановленным — бот ему больше не пишет. Запрет «Не писать» для аккаунтов партнёров (источник `bot`, только для клиента,
   чьим подписчиком был человек) ставится **только при настройке** `bot.block_stops_accounts` (выключена по умолчанию): человек мог
   не захотеть бота, но не отказаться от уведомлений вообще. Ответ «стоп» боту — отказ всегда, как и раньше (ADR-0088).
   Поле с пользователем в `bot_stopped` взято по образцу `bot_started` (`user.user_id`); нет его — событие пишется в журнал
   и пропускается. На живом боте не проверено.
2. **«Только первое» — по пути.** Первое сообщение — первое ушедшее этому номеру от этого клиента **тем же путём** (`messages.route`):
   первое через бота — первое после подписки, сколько бы ни ушло через аккаунты партнёров. Раньше считалось по всем путям,
   и блок «только первое + только бот» почти никогда не срабатывал: человек узнаёт о боте из сообщения через аккаунт.
3. **Кнопка «Отписаться» под сообщениями бота не делается:** бот и так принимает «стоп», а блокировку закрывает п. 1. Через аккаунты
   кнопок нет вовсе — у Green API для MAX нет методов с кнопками (ADR-0071, «Факт 2026-10-22»).
