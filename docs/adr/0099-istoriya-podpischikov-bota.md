# ADR-0099: История подписчиков бота MAX и статистика бота

- **Статус:** Принято — 2026-10-23; владелец: «хочется смотреть статистику по боту: сколько подключилось, отключилось и т. д.,
  максимально подробную», «да» на таблицу событий после объяснения, что статистика начнётся с дня выпуска
- **Дата:** 2026-10-23
- **Связано с:** [ADR-0077](0077-bot-max-vtoroy-kanal.md), [ADR-0087](0087-konstruktor-soobshcheniya.md),
  [ADR-0094](0094-statistika-bot-ili-akkaunty.md)

## Контекст

`bot_subscribers` хранит только текущее состояние подписки (`started`/`stopped`, номер есть или нет). По нему видно «сколько
подписано сейчас», но не «сколько запустили, поделились номером, остановили за неделю» и не воронку. Остановки к тому же до
v0.1.161 вовсе не приходили: бот не был подписан на `bot_stopped`/`dialog_removed`.

## Решения

1. **Таблица `bot_subscriber_events`**: подписка, клиент, бот, вид события, время. Виды: `started` — впервые запустил бота по
   ссылке клиента; `restarted` — вернулся после остановки; `phone_shared` — впервые поделился номером в этой подписке;
   `stopped` — остановил бота, удалил чат или ответил «СТОП» (подписка была живой). Повторный «запуск» живой подписки и
   повторный номер событий не дают — иначе счёт врал бы.
2. **Пишется той же транзакцией, что меняет подписку** (`BotsRepository`): событие и состояние не расходятся.
3. **Статистика за период** (сегодня, 7, 30 суток, свой): запустили, вернулись, поделились номером, остановили, прирост;
   подписчиков сейчас и с номером; воронка «запустили в периоде → из них поделились номером → получили сообщение →
   остановили»; по дням — запуски, номера, остановки; сообщения через бота — ушло, доставлено, не отправлено с причинами,
   сколько стоило; среднее время от запуска до номера. Список подписчиков: имя из MAX, номер, с какого числа, состояние,
   сколько сообщений получил, последнее; отбор по номеру, страницы, выгрузка.
4. **Клиенту — своё** (`/client/bot/stats`, `/client/bot/subscribers`): это его подписчики, номером они поделились с его ботом.
   Сотрудникам — то же по любому клиенту. Партнёр бота не касается.
5. **Прошлое**: миграция записывает `started` по дате подписки для имеющихся подписчиков. Когда делились номером и кто
   останавливал до выпуска — неизвестно, эти события начинаются с выпуска; в кабинете под статистикой это сказано одной строкой.

## Последствия

- Номер подписчика и раньше хранился в `bot_subscribers`; событие номер не дублирует.
- Строк немного (по нескольку на человека); индекс `(client_id, created_at)`; срока хранения нет — история нужна для сравнения
  периодов, а персональных данных в событии нет.
