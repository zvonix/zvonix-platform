# ADR-0009: Программная АТС на узлах

- **Статус:** Принято
- **Дата:** 2026-09-01

## Контекст

Узел должен: принимать SIP-регистрации GOIP-шлюзов (за NAT), принимать вызовы от клиентов,
**на каждый вызов** спрашивать маршрут у control plane, перебирать кандидатов до ответа,
писать разговор, отдавать CDR и метрики, устанавливаться одной командой и быть заменяемым.

Ключевое: вся бизнес-логика остаётся в control plane. От АТС нужна не гибкость диалплана,
а надёжное исполнение внешнего решения.

## Рассмотренные варианты

| Вариант | За | Против |
|---------|-----|--------|
| **Asterisk** (`res_pjsip` + ARI) | ARI даёт управление вызовом из внешнего кода; `MixMonitor` пишет разговор; отличная работа с NAT; самое большое сообщество, в том числе русскоязычное; проще найм | Потоковая модель: практический потолок — сотни одновременных вызовов на узел; выше расход памяти |
| **FreeSWITCH** | Событийная модель, тысячи вызовов на узел; `mod_xml_curl` запрашивает маршрут по HTTP на каждый вызов штатно; ESL для событий в реальном времени; ниже стоимость железа на тот же объём | Меньше сообщество, выше порог входа, слабее документация; сложнее найм |
| **Kamailio / OpenSIPS + RTPengine** | Десятки тысяч вызовов | Это SIP-прокси, а не АТС: запись и логика вызова требуют отдельного медиасервера. Для v1 — многократное усложнение без выигрыша |

## Решение

**FreeSWITCH.**

Определяющий довод: `mod_xml_curl` реализует ровно нашу модель — узел на каждый вызов
запрашивает маршрут по HTTP у control plane и исполняет полученное решение, не имея
собственной бизнес-логики. У Asterisk то же достигается через ARI, но менее прямо.
Плюс запас по одновременным вызовам на узел, который снижает стоимость железа при росте.

Принятая цена: выше порог входа и меньше доступных специалистов. Компенсируется тем, что
на стороне FreeSWITCH остаётся минимум — регистрация шлюзов, исполнение маршрута, запись
и отправка CDR. Вся сложность живёт в control plane на основном языке проекта, под тестами
и ревью.

## Последствия

- Положительные: маршрут запрашивается по HTTP штатным модулем, без самописных прослоек;
  запас по одновременным вызовам; событийный поток ESL для метрик и ASR в реальном времени.
- Отрицательные: выше порог входа и стоимость поиска специалиста; документация слабее,
  чем у Asterisk — конфигурация узла должна быть особенно хорошо описана в `docs/`.
- В коде: диалплан FreeSWITCH минимален и не содержит бизнес-правил. Конфигурация узла
  версионируется в репозитории и раскатывается агентом, а не правится руками на сервере.
- Путь роста: при упоре в потолок узла — Kamailio перед узлами как SIP-балансировщик,
  без изменений в control plane.
