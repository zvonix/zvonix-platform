# ADR-0013: Определение оператора по номеру (MNP)

- **Статус:** Предложено — требуется решение по источнику данных
- **Дата:** 2026-09-01

## Контекст

Канал клиента настраивается «по операторам», цена зависит от направления, а маршрутизация
выбирает шлюз, способный терминировать в нужную сеть. Всё это опирается на ответ
на вопрос: **какому оператору сейчас принадлежит номер**.

В России действует переносимость номеров (MNP): номер сохраняется при переходе абонента
к другому оператору. Префикс DEF-кода больше не определяет оператора. Ошибка определения —
это неверная цена и звонок через неподходящий шлюз, то есть прямой убыток на каждом
таком вызове.

## Изученные источники

| Источник | Что даёт | Доступ | Пригодность |
|----------|----------|--------|-------------|
| **План нумерации Роскомнадзора** | Диапазоны DEF/ABC → оператор и регион | Открытый, выгрузка файлом | Базовый слой. **Не учитывает перенесённые номера** |
| **[Таблица маршрутных номеров НИЦ Телеком](https://www.nic-t.ru/bdpn/tablica-marshrutnyh-nomerov/)** | Маршрутный номер → оператор-получатель. Формат XLS, обновление еженедельно, доступ свободный | Скачивание файла | Полезна как **расшифровщик** маршрутных номеров. Сама по себе не отвечает, перенесён ли конкретный номер |
| **БДПН (база перенесённых номеров), НИЦ Телеком** | Авторитетный ответ: текущий оператор номера. Автоматический протокол или веб-интерфейс | **Требует лицензии на услуги связи**: к заявлению прикладываются копии лицензий | Идеальный источник, но доступ упирается в [ADR-0011](0011-pravovoy-kontur.md) |
| **Коммерческие MNP / HLR-lookup сервисы** | Текущий оператор номера по запросу | Платно за запрос, лицензия не требуется | Рабочий вариант без статуса оператора |

Ключевой вывод: **таблица маршрутных номеров — не замена БДПН.** Она расшифровывает
маршрутные номера, но не говорит, что номер X перенесён. Прямой доступ к БДПН требует
лицензии оператора связи, что делает вопрос источника зависимым от правовой модели проекта.

## Решение (предлагается)

**Абстракция `OperatorResolver` с подключаемыми источниками и кэшем.**
Код маршрутизации и тарификации не знает, откуда пришёл ответ, — источник заменяется
без переписывания системы.

Порядок разрешения:

1. **Кэш** (Redis + постоянное хранение в PostgreSQL) — с TTL, потому что номер может быть
   перенесён в любой момент.
2. **Внешний lookup** при промахе кэша: БДПН, если доступ будет получен, иначе коммерческий
   сервис. Синхронно, с жёстким таймаутом.
3. **План нумерации** как запасной вариант при недоступности lookup: оператор определяется
   по префиксу, вызов помечается как **оператор не подтверждён**, и применяется
   консервативный тариф — тот, который не приносит убытка при ошибке.

Дополнительно:

- **Предразрешение списков.** Службы такси звонят относительно устойчивому набору номеров,
  поэтому попадание в кэш будет высоким, а расходы на lookup — умеренными. Клиент может
  заранее загрузить свой список номеров на разрешение пакетом.
- **Флаг в CDR**: чем определён оператор — кэшем, lookup, или планом нумерации.
  Без этого разбор спора о цене невозможен.
- **Таблица маршрутных номеров** загружается еженедельно автоматически и используется
  для расшифровки ответов, содержащих маршрутный номер.

## Последствия

- Положительные: источник данных меняется настройкой; система работает и без доступа
  к БДПН, с явной пометкой неподтверждённых определений; расходы на lookup ограничены кэшем.
- Отрицательные: при работе без БДПН часть вызовов тарифицируется консервативно, что снижает
  маржу; кэш требует продуманного TTL — слишком длинный даёт ошибки после переносов.
- В коде: определять оператора по префиксу напрямую, минуя `OperatorResolver`, запрещено.

## Открытый вопрос

Получение доступа к БДПН зависит от наличия лицензии на услуги связи — то есть от решения
по [ADR-0011](0011-pravovoy-kontur.md). До его прояснения закладываемся на коммерческий
lookup, сохраняя возможность переключения.
