# ADR-0113: Адрес SIP узла определяется сам, меняется в настройках и никогда не подменяется адресом сайта

- **Статус:** Принято
- **Дата:** 2026-11-11

## Контекст

Владелец (2026-11-11) настроил GOIP строго по кабинету, но ни одна линия не вышла на связь.
Разбор показал:

- узел АТС «тест 1» стоит на отдельной машине (`ats-zvonix-test`, 217.197.114.163), работает
  и шлёт пульс; телефония на нём отвечает на SIP;
- **адрес SIP у узла не задан**: поле заполняется только при добавлении узла, поменять его потом
  нельзя — ни в кабинете, ни в API;
- когда адреса нет ни у одного узла, площадка **молча подставляла домен сайта**
  (`TelephonyService.sipServer`). Кабинет показал партнёру `cp.zvonix.com`, и GOIP стучался
  на машину, где телефонии нет. Ошибка не видна никому: кабинет выглядит исправным, партнёр
  ищет ошибку у себя.

Владелец: «нужно нормально делать, без всяких временных IP», «может, нужно сделать, чтобы у узла
АТС были настройки?».

## Рассмотренные варианты

1. **Только сделать адрес изменяемым** — плюсы: просто. Минусы: администратор должен знать
   и вписать адрес руками; пока не вписал — та же подмена или пустое место.
2. **Адрес из пульса узла, изменяемый в настройках, без подмены** — плюсы: работает без ручного
   ввода в обычном случае (узел с публичным адресом или на машине площадки), администратор
   может поправить, ошибка «адреса нет» видна прямо. Минусы: адрес, с которого узел обращается
   к площадке, может не совпадать с адресом для GOIP (узел за NAT, отдельный адрес под SIP) —
   для этого и нужна правка руками.
3. **Узел сам сообщает адрес в пульсе** — точнее, но требует новой версии набора на каждом узле;
   до обновления узлов не работает.

## Решение

**Вариант 2.**

- **Адрес определяется сам.** Пока у узла адреса нет, площадка задаёт его по пульсу
  (и по регистрации узла): обращение с петлевого адреса — узел на машине площадки, адрес —
  домен сайта (`PUBLIC_BASE_URL`); с публичного адреса — этот адрес. С частного
  (`10/8`, `172.16/12`, `192.168/16`, `100.64/10`, IPv6 `fc00::/7`, `fe80::/10`) — ничего:
  такой адрес снаружи недоступен, его задаёт администратор. Заданный адрес пульс
  не переписывает никогда — правка администратора главнее. Журнал — `node.sip_address_detected`.
- **Настройки узла** — окно «Настройки» в строке узла: название и адрес SIP. Пустой адрес —
  «определить по пульсу заново». Журнал — `node.settings_changed`.
- **Подмены нет.** `sipServer()` возвращает `null`, если адреса нет ни у одного узла. Кабинет
  партнёра и клиента вместо адреса говорит прямо: «Площадка ещё не задала адрес для подключения»;
  администратор видит в строке узла «адрес не задан» и подсказку, где его задать.

## Последствия

- Положительные: у владельца адрес узла заполнится сам с первым пульсом после обновления;
  новый узел работает без ручного ввода; ошибка «адреса нет» видна, а не прячется за чужим адресом.
- Отрицательные и принятая цена: в ответах API поле `server` у учётных данных SIP и подключения
  может быть `null` — клиент API обязан это показать, а не подставить своё. Узел за NAT требует
  адреса руками.
- Обязательно: код не подставляет адрес сайта вместо адреса узла ни в одном месте.
