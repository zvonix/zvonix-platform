# ADR-0055: Тестовый звонок с SIM — площадка звонит сама через ESL узла

- **Статус:** Принято — 2026-09-25, решение владельца («делай что рекомендуешь»:
  тестовый звонок у партнёра и у администратора, первым — до тарифов и лимитов)
- **Дата:** 2026-09-25
- **Связано с:** [ADR-0046](0046-iniciaciya-vyzova-iz-api.md) (инициация вызова через ESL),
  [ADR-0051](0051-svoya-konfiguraciya-uzla.md) (ESL только на 127.0.0.1 со своим паролем),
  [ADR-0053](0053-liniya-goip-po-prefiksu.md) и [ADR-0054](0054-vhod-po-liniyam-goip.md)
  (как набирается линия GOIP), [ADR-0028](0028-vtoroy-faktor.md) (шифрование секретов)

## Контекст

Первый звонок через площадку до сих пор не совершён. Чтобы позвонить по нынешней модели,
нужно завести клиента, канал, баланс, цену партнёра, коридор и наценку, поставить
софтфон — и любая из этих настроек роняет звонок причиной, которая ничего не говорит
о железе. Партнёр при подключении хочет знать одно: **звонит ли вот эта SIM**.

Владелец: «для первого звонка у партнёра должна быть функция тестовый звонок с указанием
номера телефона, чтобы партнёр мог проверить конкретную SIM-карту».

## Решение

### 1. Площадка звонит сама: `originate` по ESL

Команду получает FreeSWITCH узла, на котором зарегистрирована линия SIM:

```
originate {origination_uuid=<id>,zvonix_test_call=<id>,originate_timeout=40,ignore_early_media=true}[sip_invite_req_uri=sip:<набор>@<realm>]user/<логин>@<realm> &playback(tone_stream://L=5;%(400,600,425))
```

Набор линии — тот же, что у маршрутизации: вход линии без префикса или вход шлюза
с префиксом `99NNN` (ADR-0053, ADR-0054). Строится одной функцией для обоих путей,
иначе тест проверял бы не то, чем звонит площадка. Ответивший слышит пять коротких
сигналов, после чего вызов кладётся сам.

Соединение ESL — на одну команду, как решено в ADR-0046: подключились, отдали
`api originate`, дождались ответа, закрыли. Ответ `+OK <uuid>` — ответили, `-ERR <причина>` —
причина отбоя FreeSWITCH. Клиент ESL свой, ~150 строк: протокол текстовый, а пакеты
для Node заброшены или тянут за собой постоянное соединение с событиями.

### 2. Пароль ESL узел сообщает площадке сам

ESL слушает только 127.0.0.1 (ADR-0051), пароль порождает установщик узла, и хранится
он только на узле. Узел передаёт его обработчиком `PUT /node/esl` под своим ключом.
Установщик вызывает его после записи конфигурации. Площадка хранит пароль
**зашифрованным** тем же способом, что пароль SIP-транка: утечка одной базы не даёт
права звонить.

**Только узел на той же машине, что площадка.** Адрес ESL не принимается от узла: иначе
украденный ключ узла направлял бы площадку на любой адрес и порт. Площадка соединяется
с 127.0.0.1 и принимает пароль, только если запрос пришёл с петлевого адреса. Для узла
на другой машине `PUT /node/esl` отвечает `409`, а тестовый звонок — понятным отказом.
Выставить ESL такого узла наружу (порт 8021, список адресов) — отдельная работа
из ADR-0046, строка в TASKS.

### 3. Звонок бесплатный и вне биллинга

Нет клиента, канала, резерва, проводок и цены. Нет проверки оператора номера: карта
своя, звонок идёт по её тарифу у оператора, и проверяется ровно одно — работают ли GOIP,
линия и SIM. Поэтому тестовый звонок — это не `Call`, а своя запись `test_calls`:
вызов в отчётах и сверке означал бы деньги.

CDR тестового звонка узел всё равно пришлёт. Приём CDR узнаёт его по переменной
`zvonix_test_call`, дописывает длительность разговора и код SIP и отвечает `200`.
Иначе он ответил бы `404`, и узел складывал бы такие CDR на диск как невыставленные
счета.

### 4. Ограничения

- Партнёр проверяет **только свою** SIM, администратор — любую.
- SIM должна стоять в порту шлюза с входом. Состояние SIM `new` допускается — именно
  его и проверяют при подключении. Состояния `blocked` и `retired` не допускаются, шлюз
  `retired` тоже.
- **Одна попытка в минуту на SIM** и одна одновременно. Иначе кнопка превращается
  в автодозвон, за который оператор блокирует карту.
- Номер — российский, в каноническом виде. Чёрный список площадки соблюдается.
- Запись в журнале: кто, с какой SIM. Номер в журнале маскируется.

### 5. Итог виден в кабинете

`POST …/test-call` сразу отвечает `202` с записью в состоянии `dialing`, звонок идёт
в фоне процесса API. Кабинет опрашивает запись раз в пару секунд. Если API
перезапустился посреди звонка, итог дописывает CDR. Если нет и его, запись старше
трёх минут показывается как «итог неизвестен».

Итоги: `answered` (ответили), `busy`, `no_answer`, `failed` с причиной FreeSWITCH
по-русски («линия не на связи с площадкой», «номер не существует»…).

## Последствия

- **Положительные.** Партнёр проверяет SIM сам, без клиента и цен: первый звонок
  через площадку перестаёт зависеть от биллинга. Появляется первый кусок инициации
  из ADR-0046 — клиент ESL и построение набора линии.
- **Отрицательные.** Новая дверь: процесс API может звонить. Её держат пароль ESL
  в зашифрованном виде, петлевой адрес и предел попыток. Звонок идёт за счёт SIM
  партнёра — это его проверка его карты.
- **Не проверено до живого сервера:** точный вид ответа `api originate` у FreeSWITCH
  1.10.12, пришлёт ли узел CDR при отказе до создания канала (`USER_NOT_REGISTERED`),
  слышен ли `tone_stream` через GOIP. Проверяется первым тестовым звонком.

## Ревизия 2026-09-29: без предела по времени; номер с «+»

- **Предел «раз в минуту на SIM» снят** (владелец: «убери это ограничение»). Остаётся
  «одна проба на карту одновременно» — вторая застала бы линию занятой первой.
- **Первый звонок до мобильного прошёл** (живой GoIP-4, Line 4, 2026-09-29 06:04 UTC):
  набор `sip:99004+79230189196@<адрес линии>`. Без «+» сеть отвечала `404` — SIM набирает
  номер как есть, а сам GOIP звонит `+7…`. Набор линии и строка набора каталога —
  [ADR-0054](0054-vhod-po-liniyam-goip.md), ревизия 2026-09-29.
