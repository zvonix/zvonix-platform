# ADR-0004: Структурированные логи и сквозной идентификатор запроса

- **Статус:** Принято
- **Дата:** 2026-09-01

## Контекст

В production на Ubuntu единственный способ понять, что произошло, — логи. Текстовые логи
без структуры невозможно фильтровать, а без сквозного идентификатора нельзя собрать
все записи одного запроса, особенно когда он проходит через несколько модулей и внешних
вызовов. Добавить это в уже написанный большой проект — отдельная дорогостоящая работа,
потому что трогать придётся каждую точку логирования.

## Рассмотренные варианты

1. **Печать в stdout по месту** — ноль подготовки, нулевая пригодность к разбору инцидента.
2. **Текстовые логи с уровнями** — привычно, но не фильтруется по полям и не связывает записи.
3. **Структурированные JSON-логи с обязательными полями и correlation-id** — машинно
   разбираемы, связывают записи одного запроса, готовы к отправке в любой сборщик логов.

## Решение

Вариант 3, с первого дня.

Обязательные поля каждой записи: `timestamp` (UTC, ISO-8601), `level`, `message`,
`correlation_id`, `component`. Дополнительные — структурированными полями, не склейкой в строку.

- `correlation_id` создаётся на входной границе (запрос, задача, сообщение из очереди),
  прокидывается через все слои и передаётся во внешние вызовы. Он же возвращается клиенту
  в ответе об ошибке — по нему инцидент находится за один поиск.
- Уровни: `error` — сломалось, требует реакции; `warn` — деградация, работа продолжается;
  `info` — значимые события домена; `debug` — детали, в проде выключены.
- **Никогда не логируются**: пароли, токены, ключи, содержимое `.env`, номера карт,
  персональные данные сверх необходимого. Для потенциально чувствительных полей —
  маскирование в логгере, а не самодисциплина в точках вызова.
- Локально (Windows) допускается человекочитаемый вывод, в production — строго JSON.
  Это единственное различие сред.

## Последствия

- Положительные: инцидент разбирается по `correlation_id`; логи пригодны для любого сборщика
  без переделки; чувствительные данные не утекают.
- Отрицательные: correlation-id нужно явно прокидывать через слои; логгер нельзя обойти.
- В коде: прямая печать в консоль вместо логгера — нарушение.
