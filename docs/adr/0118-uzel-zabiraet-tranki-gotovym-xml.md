# ADR-0118: Узел забирает SIP-провайдеров готовым файлом FreeSWITCH

- **Статус:** Принято — 2026-11-13, решение владельца («делай всё, что рекомендуешь»)
- **Дата:** 2026-11-13
- **Дополняет:** [ADR-0039](0039-terminaciya-cherez-sip-trank.md) — там конфигурацию исходящих sofia-gateway
  собирал «агент узла» из `GET /node/sip-gateways`, а агента так и не сделали
- **Связано с:** [ADR-0051](0051-svoya-konfiguraciya-uzla.md) (каталог `zvonix-gateways/`),
  [ADR-0100](0100-sip-provayder-partnyora-i-vklyuchenie-posle-proby.md) (проба SIP-провайдера),
  [ADR-0114](0114-uzel-sam-soobshchaet-registracii.md), [ADR-0115](0115-uzel-zabiraet-komandy.md)

## Контекст

Партнёр завёл SIP-провайдера, и тестовый звонок через него ответил `INVALID_GATEWAY` (владелец, 2026-11-13).
Площадка набирает `sofia/gateway/<имя>/<номер>`, но на узле такого gateway нет: каталог `zvonix-gateways/`
подключён в профиль `zvonix`, а наполнять его должен был агент узла, которого нет. Ни один SIP-провайдер
ни на одном узле не поднимался.

Агента на Node или Go ради этого не заводим: работу агента сейчас делают скрипты `install.sh` (пульс,
регистрации, команды). На узле только shell без `jq`, а собирать XML из JSON с чужими паролями в shell —
верный способ однажды получить битый файл и уронить все транки при `reloadxml`.

## Решение

1. **Площадка отдаёт готовый файл**: `GET /node/sip-gateways.xml`, по ключу узла, только его действующие транки.
   Внутри `<include>` — **по одному `<gateway>` на строку**, все значения экранированы, переводы строк тоже.
   Параметры: `proxy`, `realm` (адрес провайдера без порта), `register`, `username`, `password`, срок
   регистрации 600 с, повтор 30 с. Без регистрации (провайдер узнаёт по адресу) `username` — `zvonix`:
   FreeSWITCH без него gateway не поднимает. JSON-обработчик `GET /node/sip-gateways` остаётся для будущего агента.
2. **Узел забирает файл в каждом пульсе** (раз в 30 с) и сравнивает с `zvonix-gateways/zvonix.xml`.
   Не изменился — ничего не делает. Изменился — снимает пропавшие и изменённые транки (`killgw`: строки больше
   нет в новом файле), кладёт новый и делает `reloadxml` + `sofia profile zvonix rescan`. Профиль не
   перезапускается, разговоры через GOIP и другие транки не рвутся.
3. **Сбой не стирает провайдеров**: площадка недоступна или ответ не начинается с `<include>` и не кончается
   `</include>` — прежний файл остаётся.

## Последствия

- Новый или изменённый SIP-провайдер появляется на узле не позже чем через 30 с после сохранения; включение
  после пробы (ADR-0100) больше не упирается в «нет такого gateway».
- Пароль провайдера лежит на узле в файле, доступном только `freeswitch` и root (0640, каталог 0750), — как
  и раньше предполагал ADR-0039.
- Изменение `install.sh` меняет версию набора: узлы с включённым `nodes.auto_update` обновятся сами.
- Не наблюдалось на живом провайдере: ответ на `407`, поведение при превышении ёмкости — список
  в [node/README.md](../../node/README.md), «SIP-транки: чего никто не наблюдал».
