# ADR-0088: Отчёты по сообщениям MAX и защита аккаунтов от блокировок

- **Статус:** Принято — 2026-10-20; владелец: «отчёты и логи, которые рекомендуешь», «СТОП галочкой у партнёра и полем в шаблоне»,
  «рекомендованные лимиты — параметры в админке, партнёрам не показывать», «если не прочитал — следующее позже»; порядок работ
  утверждён им же, держаться его
- **Дата:** 2026-10-20
- **Связано с:** [ADR-0071](0071-soobscheniya-max.md), [ADR-0078](0078-progrev-akkauntov-max.md) (прогрев),
  [ADR-0079](0079-raspredelenie-soobscheniy-i-zdorove-akkauntov.md) (здоровье аккаунтов), [ADR-0077](0077-bot-max-vtoroy-kanal.md),
  [ADR-0087](0087-konstruktor-soobshcheniya.md), [ADR-0005](0005-migracii.md)

## Контекст

Аккаунты партнёров — экземпляры стороннего провайдера, MAX блокирует их за поведение: объём, много номеров без MAX, жалобы.
Площадка видела только текущее состояние аккаунта, а не историю и не причины; ответы людей («СТОП») через аккаунты не читались.

## Решение (порядок утверждён владельцем)

1. **Отчёты для сотрудников — сделано.** `GET /messages/report?days=` (роли `admin`, `support`; 1–90, по умолчанию 7): по клиентам и по
   аккаунтам — принято, ушло, доставлено, прочитано, не отправлено с разбивкой по причинам, ушедшие через аккаунты старше суток и из них
   прочитанные. Страница «Отчёты MAX» в меню сотрудников. Новых таблиц нет: всё считается по `messages`. «Не прочитано» не считается у
   сообщений бота (статуса «прочитано» у бота нет) и у свежих (младше суток); меньше 20 ушедших — прочерк. Подсвечивается доля
   непрочитанных от 70 % и отказов «нет MAX» от 30 %. Чего отчёт **не** показывает: историю блокировок (у аккаунта хранится только
   текущее состояние) — её даст журнал здоровья (шаг 4).
2. **«СТОП» для аккаунтов партнёров** (следующий шаг, нужна миграция). Приём входящих от провайдера; ответ «СТОП» заносит номер в
   общий список «не писать»: ему не пишет никто, ни аккаунтами, ни ботом; сообщение на такой номер отклоняется до списания денег.
   У партнёра галочка «Добавлять строку про СТОП» для его аккаунтов; клиенты видят, на каких путях строка включена, а предпросмотр
   в конструкторе показывает её. Приём ответов работает всегда, независимо от галочки.
3. **Рекомендованная работа аккаунта.** У партнёра одна галочка; значения (пауза, минута, час, сутки, прогрев) задаёт администратор
   в «Настройки площадки» и партнёру не показываются. Партнёр может поставить свои значения только ниже рекомендованных.
4. **Журнал проверок номеров на MAX и здоровья аккаунтов** (таблицы): сейчас результат проверки живёт только в памяти Redis, а
   пауза аккаунта — единственная строка состояния. Журнал даёт историю для отчёта «блокировок на тысячу сообщений».
5. **Лестница «не прочитал»** (1 → 3 → 7 → 30 суток): правило по клиенту, включает администратор, по умолчанию выключено; не для
   кодов подтверждения. Строится после нескольких недель данных отчётов и проверки, что статусы «прочитано» доходят.

## Последствия

- Шаг 1 не меняет схему и контракты существующих путей; добавлен только новый путь чтения.
- Шаги 2–5 каждый получают свою ревизию этого ADR и миграцию перед реализацией.
- Рекомендованные цифры лимитов выдумывать нельзя: они выставляются по данным отчётов с живых аккаунтов.
