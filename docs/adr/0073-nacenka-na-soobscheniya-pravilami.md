# ADR-0073: Наценка на сообщения — теми же правилами, что и на звонки

- **Статус:** Принято — 2026-10-05, решение владельца: «нужна гибкая настройка — на каждое сообщение и в
  процентах; одинаково на звонки и на сообщения»
- **Дата:** 2026-10-05
- **Связано с:** [ADR-0071](0071-soobscheniya-max.md) (п. 3 — наценка настройкой), [ADR-0010](0010-model-billinga.md),
  `commission_rules`

## Контекст

В ADR-0071 наценка на сообщения — одна настройка `messages.markup_percent`. Владельцу этого мало: нужны
процент **и** фиксированная сумма за сообщение, особые условия для отдельного клиента, даты начала действия —
всё то, что у наценки на звонки (`commission_rules`). Два разных механизма для одного понятия «наценка площадки»
путают: владелец ожидает одинаковый вид и поведение.

## Решение

1. **Одна таблица правил** `commission_rules` с колонкой `product` (`call` | `message`, по умолчанию `call`).
   Правило: клиент (пусто — для всех), доля от цены партнёра, фиксированная сумма за единицу (вызов или
   сообщение), дата начала действия. Записи не редактируются, а добавляются (ADR-0010): действует самое свежее
   подходящее, правило клиента перебивает общее.
2. **Наценка на сообщение = фикс + доля × цена партнёра**, округление вверх до микроединицы (ADR-0010), как и
   прежде; применяются вместе. Фиксируется на сообщении при приёме (ADR-0071) — новые правила уже принятое не
   переоценивают.
3. **Пределы.** Доля у звонков — до 100 % (как было); у сообщений — до 1000 %: цена партнёра за сообщение
   копеечная, и наценка в сотни процентов — обычное дело. Проверяется в базе и при приёме.
4. **Настройка `messages.markup_percent` удаляется**: источник один. Миграция переносит её сохранённое значение
   (или 20 % по умолчанию) в общее правило сообщений и стирает строку настройки.
5. **API.** `GET /commission-rules?product=call|message`, `POST /commission-rules` с необязательным
   `product` (по умолчанию `call`). Вид правила получает `product`. Кабинет: одна и та же таблица на странице
   «Тарифы и наценка» для обоих продуктов.
6. **Цена для клиента** (`GET /client/messages/price`) считается по правилу этого клиента, а не одна на всех.

## Следствия

- Миграция `0044`: колонка `product`, замена проверки доли, перенос настройки.
- Тарификация звонков не меняется: поиск правила для вызова фильтрует `product = 'call'`.
- Для сообщений правила всегда есть (общее заведено миграцией); отсутствие правила — наценка 0, а не отказ.
