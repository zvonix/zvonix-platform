# ADR-0097: «Все заняты» — отказать сразу или ждать; срок у сообщения

- **Статус:** Принято — 2026-10-22; владелец: «если все каналы заняты, мы ничего не отправляем программе… программа ждёт статусы и
  потом помечает „удалён по таймеру“», «„сколько сообщение ждёт отправки“ — сделать настройкой клиенту: есть срочные сообщения и не
  срочные», «делай что рекомендуешь»
- **Дата:** 2026-10-22
- **Связано с:** [ADR-0072](0072-smpp-dlya-soobscheniy.md), [ADR-0076](0076-statusy-smpp-po-nastrojkam-klienta.md),
  [ADR-0079](0079-raspredelenie-soobscheniy-i-zdorove-akkauntov.md)

## Контекст

Сейчас при приёме сообщения, если свободного аккаунта нет, оно встаёт в очередь к «первому по давности» и ждёт до
`messages.max_wait_minutes` (30 минут, одна настройка на площадку); не ушло — отказ `wait_expired` (SMPP — `EXPIRED`) с возвратом
денег. Программа такси столько не ждёт: помечает «удалён по таймеру» и не шлёт через другого агрегатора, а «машина прибыла» через
20 минут уже вредна. Отказ сразу есть только когда рабочих аккаунтов нет вовсе (`ESME_RTHROTTLED`).

## Решения

1. **Настройка клиента «Если отправить сразу нельзя»** (`busy_mode`): `reject` — отказать сразу (SMPP `ESME_RTHROTTLED`, API `503`
   «все заняты — повторите»), программа уходит к другому агрегатору; `wait` — ждать в очереди. **Не задана — по каналу:** SMPP —
   `reject`, API и кабинет — `wait` (у них поведение не меняется).
2. **Сколько ждать** (`max_wait_minutes`, 1–1440) — у клиента; не задано — `messages.max_wait_minutes` площадки.
3. **Срок у сообщения:** SMPP `validity_period` (SMPP 3.4: абсолютный `YYMMDDhhmmsstnn±` и относительный `…R`), API — `validMinutes`
   (1–1440). Действует **меньшее** из срока сообщения и «сколько ждать»; срок уже прошёл при приёме — отказ.
4. **Срок записывается в сообщение** (`messages.expires_at`) при приёме; просроченное не уходит и деньги возвращаются (прежний
   `wait_expired` / `EXPIRED`). Старые строки без срока — по прежнему правилу от времени приёма.
5. **Ждать бессмысленно — отказ сразу и в режиме `wait`:** если ближайший аккаунт по своим лимитам освободится позже срока
   сообщения, программа получает отказ при приёме, а не `EXPIRED` через полчаса.
6. **Бот** не «занят»: сообщение подписчику уходит сразу; срок записывается и там.
7. Настройки — в «Подключениях» клиента (`PUT /client/messages/delivery`), в журнал действий (`client_message_delivery.set`).

## Последствия

- Миграция: колонка `messages.expires_at` и две колонки у `client_message_requirements` (обе пустые по умолчанию — поведение
  прежних клиентов API не меняется, SMPP-клиенты начинают получать отказ сразу вместо долгого ожидания).
- Отказ при приёме не списывает деньги вовсе — проводки нет.
