# ADR-0050: Установка одной командой и первый вход по одноразовому коду

- **Статус:** Принято — 2026-09-22, решение владельца площадки
- **Дата:** 2026-09-22
- **Связано с:** [ADR-0018](0018-autentifikaciya.md) (аутентификация),
  [ADR-0028](0028-vtoroy-faktor.md) (ключ приложения и выводимые из него ключи),
  [ADR-0041](0041-predel-chastoty-izmeneniy.md) (пределы частоты),
  [ADR-0049](0049-vykladka-ploshchadki.md) (выкладка)

## Контекст

Первая выкладка на тестовый сервер 2026-09-22 прошла, но до работающей площадки
осталось три ручных шага: вписать токен GitHub в `/etc/zvonix/github.env`, запустить
выкладку отдельной командой и завести администратора командой в терминале, передав
почту и пароль через переменные окружения. Владелец попросил: **одна команда
установки, а логин и пароль администратора задаются при первом открытии сайта.**

Первого администратора нельзя заводить правилом «кто первым открыл сайт — тот
администратор»: комментарий к `create-admin.ts` называет причину — окно между
выкладкой и первым входом отдаёт полный доступ любому, кто узнал адрес. У площадки
с деньгами клиентов адрес найдут.

## Решение

### 1. Первый вход по одноразовому коду

Пока на площадке **нет ни одной учётной записи с ролью `admin`** (в любом состоянии),
кабинет вместо входа показывает форму «Первый запуск»: код, почта, имя, пароль.
Код видит только тот, кто запускал установку: его печатает выкладка.

- **Код выводится из `SECRET_KEY`, а не хранится.** `HMAC-SHA256` ключом, выведенным
  из `SECRET_KEY` с назначением `zvonix:first-run-code:v1` (как ключи ADR-0028), от номера
  суток UTC. Двенадцать знаков base32 — 60 бит, показывается группами `XXXX-XXXX-XXXX`.
  Принимаются коды текущих и прошлых суток: код живёт от суток до двух.
  Хранить нечего — ни таблицы с миграцией, ни ключа в Redis, который пропал бы
  с его перезапуском. Узнать код может только тот, у кого есть `SECRET_KEY`, то есть
  root на сервере, — он и так владеет площадкой.
- **Закрывается навсегда сам:** как только администратор есть, форма отвечает «первый
  запуск уже выполнен», и код ничего не открывает. Отдельной отметки «использован» нет —
  её роль играет само существование администратора.
- **Гонка двух форм с верным кодом** закрыта рекомендательной блокировкой в транзакции:
  проверка «администратора нет» и заведение идут под одной блокировкой, второй получает
  `409`.
- **Перебор кода:** 60 бит перебором не берутся; поверх — предел частоты по адресу,
  как у регистрации (ADR-0041 для открытых путей). Предел проходной при недоступном
  Redis, и защиту несёт длина кода, а не предел.
- Самостоятельно зарегистрированные клиенты и партнёры первый запуск не закрывают:
  регистрация открыта до появления администратора, и иначе чужая регистрация
  запирала бы площадку.
- Заведение пишется в журнал действий (`user.first_admin_created`, адрес источника).

Команда `admin:create` остаётся: ею заводятся поддержка и администратор на сервере
без кабинета.

### 2. Установка одной командой

`deploy/install.sh` — маленький загрузчик. Одна строка в терминале сервера спрашивает
токен GitHub скрытым вводом, скачивает `install.sh` из репозитория по этому токену
и запускает его:

1. узнаёт последний выпуск и скачивает исходники этой метки — из них берётся каталог
   `deploy/` той же версии, что и выпуск;
2. запускает `server-setup.sh` — он, как и раньше, ставит пакеты, nginx и файрвол,
   а теперь ещё записывает переданный токен в `github.env`, если там пусто;
3. запускает `zvonix-deploy <метка>` — выкладку ADR-0049 без изменений;
4. выкладка, если администратора нет, печатает код первого запуска и адрес кабинета.

Токен в командной строке не появляется: он передаётся переменной окружения
(`sudo --preserve-env`), а не аргументом — аргументы видны в списке процессов.

## Последствия

- **Положительные.** Новый сервер — одна строка и одна форма в браузере. Пароль
  администратора не проходит через терминал, историю оболочки и чужие руки.
- **Цена.** Новый открытый адрес API (`GET/POST /setup`) и страница кабинета. Код
  привязан к `SECRET_KEY`: смена ключа меняет код — это не вредно, выкладка печатает новый.
- **Проверка.** Код и окно суток — модульные тесты; заведение, отказы и гонка — тесты
  с базой; страница — сквозной тест. Установка одной командой проверяется только живым
  сервером.
