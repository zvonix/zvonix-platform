# ADR-0077: Бот MAX — второй канал сообщений, цена за бота и за сообщение

- **Статус:** Принято — 2026-10-08, решение владельца: «единый бот площадки с ценой использования, а клиенты могут
  подключить своего бота; цена — ежемесячная плата и за сообщения, в обоих полях можно поставить 0»; профиль
  организации в MAX для бизнеса у владельца есть
- **Дата:** 2026-10-08
- **Связано с:** [ADR-0071](0071-soobscheniya-max.md), [ADR-0072](0072-smpp-dlya-soobscheniy.md),
  [ADR-0073](0073-nacenka-na-soobscheniya-pravilami.md), [ADR-0010](0010-model-billinga.md),
  [ADR-0016](0016-soglasheniya-shemy-bd.md), факты о платформе — [docs/api/max-bots.md](../api/max-bots.md)

## Контекст

Сообщения уходят с личных аккаунтов MAX партнёров. Это работает на любой номер с MAX, но несёт риск блокировки
аккаунтов. Бот — официальный канал MAX (токен выдаёт платформа, вебхук с секретом), без риска блокировки, но с жёстким
ограничением: **бот пишет только тому, кто сам его запустил** и поделился номером. Создать бота можно только вручную
в «MAX для бизнеса» (до 5 на организацию, модерация до 48 часов), через API — нельзя
([max-bots.md](../api/max-bots.md)). Поэтому «свой бот у каждого клиента, созданный площадкой» невозможен, а бот —
дополнительный канал, а не замена аккаунтам.

## Решение

1. **Два вида ботов** (`messenger_bots.kind`): `platform` — один бот площадки, токен вписывает администратор;
   `client` — бот клиента, токен вставляет сам клиент (этап 2). Токен хранится зашифрованным, как токены аккаунтов
   (`secret-box`, своя цель). При записи площадка проверяет токен у MAX (`GET /me`) и сама настраивает вебхук
   (`POST /subscriptions`: адрес площадки, `update_types = bot_started, message_created`, секрет бота, который
   MAX присылает в `X-Max-Bot-Api-Secret`).
2. **Подключение клиента к боту** — таблица `bot_connections` (одна на клиента): бот (площадки или свой), включено ли,
   публичный код клиента (его пассажиры приходят по ссылке `https://max.ru/<имя бота>?start=<код>`), цены этого клиента
   (необязательные, пусто — как у площадки), период, за который взята ежемесячная плата.
3. **Подписчики** — таблица `bot_subscribers`: бот, клиент, пользователь MAX, чат, **номер** (появляется, когда человек
   нажимает «Поделиться номером»), состояние (`started` / `stopped`). Номер принимается **только из контакта, который
   человек прислал о себе** (`max_info.user_id` равен отправителю): чужой контакт не создаёт привязки. «СТОП» — отписка,
   сообщения ему больше не идут.
4. **Порядок отправки** (владелец): сначала бот — если клиент подключён к боту, а у номера есть подписчик с этим номером в
   состоянии `started`; иначе обычный путь через аккаунты партнёров (проверка наличия MAX из ADR-0071 п. «предпроверка»);
   иначе отказ. Отдельной настройкой клиент может отключить запасной путь через аккаунты.
5. **Сообщение бота — та же строка `messages`**, чтобы клиент видел всё в одном журнале, а SMPP и API работали как
   прежде: `route = 'bot'`, `bot_id`, без аккаунта и партнёра (`account_id`, `partner_id` необязательны). Состояние
   «доставлено» ставится, когда MAX принял сообщение (отчёта о прочтении у бота нет). Отказ MAX («пользователь
   остановил бота») — окончательный, деньги возвращаются, подписчик помечается `stopped`.
6. **Деньги.** Клиент платит площадке: проводка «клиент → доход площадки» (`chargeBotMessage`), партнёру ничего.
   Цена — **две независимые настройки**, каждая от 0: **цена за сообщение** и **ежемесячная плата за пользование ботом**.
   Для бота площадки и для бота клиента — свои значения по умолчанию (`bot.message_price`, `bot.monthly_fee`,
   `bot.own_message_price`, `bot.own_monthly_fee`) и необязательное исключение на конкретного клиента в
   `bot_connections`. Правило наценки ADR-0073 к боту не применяется: цена и есть цена площадки.
7. **Ежемесячная плата** — периодическое списание: ключ идемпотентности `bot_fee:<клиент>:<ГГГГ-ММ>`; берётся при
   подключении (если за месяц ещё не брали) и воркером в начале каждого месяца (UTC), по ним же — догоняюще (ADR-0020).
   Не хватило денег — подключение приостанавливается (сообщения идут запасным путём), пока клиент не пополнит счёт;
   возврата платы за месяц при отключении нет.
8. **Выключатель** — настройка `bot.enabled` (по умолчанию выключено): пока администратор не вписал бота и не включил
   продукт, кабинеты бота не показывают, а отправка идёт как раньше.
9. **Сообщения самого бота людям** (приветствие, запрос номера, подтверждение, ответ на «СТОП») — наши готовые тексты
   с названием службы клиента; настраиваемые тексты (приветствие, до/после сообщения) — этап 3.

## Этапы

1. Бот площадки: таблицы, провайдер MAX Bot API (с имитацией для тестов), регистрация администратором, вебхук,
   подписчики, ссылка и QR у клиента, отправка с маршрутизацией, деньги, ежемесячная плата, цены.
2. Бот клиента: клиент вставляет токен, проверка и вебхук тем же кодом, цены `own_*`.
3. Настройки текстов бота клиента и «запасной путь через аккаунты» — переключатель. **Сделано 2026-10-08**
   (`bot_connections.greeting`, `text_before`, `text_after`, `fallback_accounts`; миграция 0051).

## Риски и оговорки

- Бот не заменяет аккаунты: у незнакомого пассажира подписки нет, он идёт запасным путём. Ценность бота — службам,
  которые сами приводят пассажиров по ссылке (в приложении, в чеке, на заказе).
- Вебхук требует HTTPS на 443 с доверенным сертификатом; площадка с доменом и Let's Encrypt это выполняет. Если MAX
  8 часов не получает ответа 200, он сам отписывает бота — состояние бота в кабинете администратора проверяется кнопкой.
- Персональные данные: номер и идентификатор MAX хранятся только у подписчика, номер маскируется в логах (CLAUDE.md).
- Лимит MAX на отправку в один чат — 2 сообщения в секунду; общий предел в документации не указан, при 429 сообщение
  остаётся в очереди и повторяется.

## Не входит

Рассылки без подписки; бот как приёмник ответов пассажиров к клиенту (ответы — как в ADR-0071, «Не входит»);
несколько ботов на клиента; создание ботов через API (его нет).
