# ADR-0061: Выгрузка в CSV

- **Статус:** Принято — 2026-10-01, решение владельца («делай что рекомендуешь»)
- **Дата:** 2026-10-01
- **Связано с:** [ADR-0014](0014-vybor-partnera-klientom.md) (кто что видит),
  [ADR-0059](0059-otchyoty-i-svodki.md) (сводки), [ADR-0037](0037-sessiya-v-brauzere.md)

## Контекст

Клиенту нужно сверить вызовы со своей АТС, партнёру — со счётом оператора, бухгалтеру — свести
сводку в таблицу. Смотреть пятьдесят строк на странице для этого мало.

## Решение

Кнопка **«Скачать таблицу»** (файл CSV) на страницах вызовов трёх кабинетов и у сводок (по дням и по
текущему разрезу). Файл собирается **в браузере из тех же ответов API**, что рисуют экран:
страницы вызовов читаются подряд по 200 строк под текущим отбором, сводка берётся уже
загруженная.

- **Новых адресов API нет.** Каждая роль выгружает ровно то, что видит на экране
  (ADR-0014: клиент без партнёра, партнёр без клиента и цены, маржа только сотрудникам).
  Отдельный серверный путь выгрузки пришлось бы проверять на приватность заново и держать
  в согласии с видами ответов.
- **Предел — 10 000 строк.** Больше браузеру собирать в памяти незачем; при усечении рядом
  с кнопкой остаётся пометка «сузьте период», молча обрезанный файл недопустим.
- **Формат для русской Excel:** разделитель `;`, метка порядка байтов UTF-8, строки CRLF,
  дробная часть сумм и долей — запятой.
- **Защита от формул.** Ячейка, начинающаяся с `=`, `@` или `+/-` перед не-цифрой, получает
  апостроф: имя линии или клиента, заданное человеком, не станет командой в чужой таблице.
  Номера и суммы со знаком не затрагиваются.

## Не входит

Серверная выгрузка для очень больших периодов (потребует очереди и объектного хранилища),
выгрузка проводок и актов — вместе со счетами и сверкой, см. [BACKLOG.md](../BACKLOG.md).

## Последствия

- Выгрузка не отдаёт ничего сверх экрана, поэтому отдельного журнала обращений нет: чтение
  вызовов и так не журналируется.
- Время сборки — число страниц × ответ API (до 50 обращений подряд); кнопка на это время
  заблокирована.
