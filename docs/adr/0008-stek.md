# ADR-0008: Технологический стек

- **Статус:** Предложено — требуется решение
- **Дата:** 2026-09-01

## Контекст

Система состоит из control plane (деньги, тарифы, права, маршрутизация в реальном времени),
кабинетов трёх ролей и агента на узлах АТС. Определяющие требования:

- **Корректность денег важнее всего.** Ошибка в тарификации — прямой убыток.
- **Маршрутное решение синхронно в цепочке вызова**: узел АТС ждёт ответа, бюджет — десятки
  миллисекунд, иначе растёт задержка ответа абонента.
- Много фоновой работы: сверка CDR, выплаты, агрегация статистики, контроль ASR.
- Админка и два кабинета — существенный объём интерфейса.

## Рассмотренные варианты

| Вариант | За | Против |
|---------|-----|--------|
| **Python 3.12 + FastAPI** | Быстрая разработка; строгая типизация с Pydantic v2 и mypy; зрелый SQLAlchemy 2.0 + Alembic; async держит требуемую задержку; много разработчиков | Медленнее Go на CPU-нагрузке; GIL требует внимания к фоновым задачам |
| **Go** | Наивысшая производительность и предсказуемость; один бинарник — удобно для агента узла | Медленнее разработка админки и CRUD; слабее экосистема для сложных доменных моделей; дороже найм под этот класс задач |
| **Node.js / NestJS** | Один язык с фронтендом | Нет нативного десятичного типа — для денег требует внешних библиотек в каждом вычислении, это системный риск в биллинге |

## Решение (предлагается)

**Control plane:** Python 3.12 · FastAPI · SQLAlchemy 2.0 · Alembic · Pydantic v2 ·
ruff · mypy в строгом режиме · pytest.

**Хранилища:** PostgreSQL 16 (домен, деньги, CDR) · Redis 7 (счётчики лимитов, кэш) ·
MinIO, S3-совместимое (записи разговоров).

**Фоновые задачи:** ARQ (async-native, работает на том же Redis). Все задачи, меняющие
деньги, — идемпотентны и публикуются через transactional outbox.

**Фронтенд:** React + TypeScript · Vite · TanStack Query · shadcn/ui.
Выбран в том числе потому, что MCP-серверы `shadcn` и `@21st-dev/magic` уже подключены
и ускоряют работу именно с этой связкой.

**Агент узла:** Go — один статический бинарник без зависимостей, что делает установку
одной командой надёжной на любом дистрибутиве. Это единственное отступление от одноязычности,
и оно оправдано способом доставки.

**Метрики:** Prometheus + Grafana.

## Последствия

- Положительные: скорость разработки при строгой типизации; деньги считаются целыми числами
  в микроединицах, без плавающей точки; агент устанавливается без рантайма на узле.
- Отрицательные: два языка в проекте; при росте нагрузки на `routing` может потребоваться
  вынести его в отдельный сервис.
- В коде: `mypy --strict` обязателен; плавающая точка в денежных вычислениях запрещена.
