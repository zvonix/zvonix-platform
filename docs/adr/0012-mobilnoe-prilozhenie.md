# ADR-0012: Мобильное приложение — телефон партнёра как шлюз

- **Статус:** Принято
- **Дата:** 2026-09-01

## Контекст

Заявлено: приложение для Android, позволяющее звонить через телефон.
Рассматривались два разных продукта.

**Вариант А — партнёрское приложение, телефон вместо GOIP.** Android-телефон с SIM получает
от платформы задание и совершает вызов через собственную SIM. Снижает порог входа для
партнёров: оборудование покупать не нужно.

**Вариант Б — клиентский софтфон.** SIP-клиент для сотрудников службы такси; вызов идёт
обычным маршрутом через платформу на шлюз партнёра.

## Ключевое ограничение варианта А

**На Android 10 и новее запись телефонного разговора недоступна обычному приложению.**
Источник звука `VOICE_CALL` закрыт и доступен только системным приложениям с соответствующей
ролью. По каналам, терминируемым через телефон, **записи разговоров не будет**.

Обходные пути неприменимы к массовому партнёру: кастомная прошивка, root, внешний
аудиоаксессуар.

Прочие сложности: удержание фонового процесса против Doze и вендорских оптимизаций
автозапуска; расход батареи; нестабильность соединения; качество звука ниже, чем у GOIP.

## Решение

**Вариант А.** Ограничение по записи принято сознательно и закрывается разделением каналов
на два класса.

Из этого следует:

1. **`Gateway.type`** принимает значения `goip` и `android`. Телефон-шлюз — это обычный
   шлюз партнёра с другим транспортом, а не отдельная сущность. Модель данных не раздваивается.
2. **`Channel.recording_required`** — флаг у канала клиента. Если запись обязательна,
   маршрутизация **исключает** шлюзы типа `android` из числа кандидатов.
3. **Цена различается.** Канал без записи дешевле — иначе клиент не имеет причин от неё
   отказываться, и Android-шлюзы не получат трафика.
4. **Клиент видит это явно** в интерфейсе при создании канала: «запись разговоров недоступна»
   с объяснением причины. Обнаружить отсутствие записи постфактум — гарантированная жалоба.
5. **В CDR фиксируется тип шлюза**, которым терминирован вызов, и был ли записан разговор.
   Без этого разбор обращения «где запись» невозможен.

## Последствия

- Положительные: порог входа для партнёров резко снижается — телефон есть у каждого;
  рост числа партнёров без вложений в оборудование.
- Отрицательные: два класса каналов усложняют маршрутизацию, тарификацию и интерфейс;
  качество и стабильность Android-канала ниже; поддержка вендорских прошивок — постоянная
  статья расходов.
- В коде: маршрутизация обязана учитывать `recording_required`; отдать вызов с обязательной
  записью на `android`-шлюз — ошибка уровня инварианта, а не недосмотр.
- Отложено: клиентский софтфон (вариант Б) — отдельным этапом, архитектуре не противоречит.
