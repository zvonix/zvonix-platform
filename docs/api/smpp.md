# Контракт: подключение клиента по SMPP

Основание — [ADR-0072](../adr/0072-smpp-dlya-soobscheniy.md). Протокол — SMPP 3.4, подмножество для отправки
сообщений MAX ([messaging.md](messaging.md)). Сообщение, принятое по SMPP, — то же сообщение, что и по HTTP:
те же цена, списание, очередь и возврат.

## Подключение

Адрес — хост кабинета и порт, который включил владелец (`SMPP_PORT`, обычный TCP; `SMPP_TLS_PORT` — TLS 1.2+).
Клиент берёт имя и пароль в кабинете: «Сообщения MAX» → «Подключение по SMPP».

| Вход | Что можно |
|---|---|
| `bind_transmitter` | отправлять (`submit_sm`) |
| `bind_receiver` | получать отчёты о доставке (`deliver_sm`) |
| `bind_transceiver` | и то, и другое |

- `system_id` — не длиннее 16 знаков, выдаёт площадка (`zx` и восемь знаков). Пароль — 16 знаков; некоторые
  старые системы режут пароль до 9 знаков — такая система не подключится, нужен клиент без этого предела.
- Отказы входа: неверное имя **или** пароль — `ESME_RINVPASWD` (0x0E; имена не различаются, чтобы их нельзя
  было перебирать); адрес не в списке, подключение отключено, клиент не работает, продукт выключен,
  слишком много сессий — `ESME_RBINDFAIL` (0x0D). После отказа соединение закрывается.
- Защита: 5 неверных входов с адреса за минуту — адрес не принимается до конца минуты; не больше 5 сессий
  на учётную запись, 20 — на адрес, 500 — всего. Не вошедший за 10 с отключается; тишина дольше 90 с —
  отключение (сервер шлёт `enquire_link` после 30 с тишины). Клиент может слать `enquire_link` сам.

## `submit_sm`

- Получатель — `destination_addr`, российский номер (`79001234567`, `+7…`, `8…` приводятся к одному виду).
  Плохой номер — `ESME_RINVDSTADR` (0x0B).
- Текст — `short_message` или TLV `message_payload` (0x0424); не пустой и не длиннее 4000 знаков, иначе
  `ESME_RINVMSGLEN` (0x01).
- Кодировка `data_coding`: **8** — UCS-2 (UTF-16BE, нужна для кириллицы); **0**, **1** — UTF-8, а если байты
  им не являются, Latin-1; **3** — Latin-1. Остальные (двоичные) — `ESME_RSUBMITFAIL` (0x45).
  Упакованный GSM 03.38 (7 бит) не поддерживается.
- Длинный текст по частям — через UDH (`esm_class` 0x40, 8- и 16-битная ссылка) или TLV `sar_*`. Части
  одной ссылки склеиваются в **одно** сообщение, оно списывается один раз. На не последние части приходит
  `ESME_ROK` с условным идентификатором, на последнюю — с настоящим. Если остальные части не пришли
  за 60 с, текст отбрасывается (запись в журнале площадки); надёжнее слать длинный текст одним
  `message_payload`.
- Ответ: `ESME_ROK` и `message_id` — идентификатор сообщения, тот же, что в кабинете и в `/v1/messages`.
- Отказы: не хватает денег или клиент не работает — `ESME_RSUBMITFAIL` (0x45); нет доступных аккаунтов,
  слишком часто (более 50 сообщений в секунду с сессии, более 100 в очереди) — `ESME_RTHROTTLED` (0x58),
  клиент повторяет сам; сбой площадки — `ESME_RSYSERR` (0x08).
- Повтор после обрыва создаёт **второе** сообщение: у протокола нет ключа повтора. Нужна защита от
  повторов — HTTP с `externalId`.
- Операции вне подмножества (`query_sm`, `cancel_sm`, `replace_sm`, `data_sm`, …) — `generic_nack`
  с `ESME_RINVCMDID` (0x03).

## Отчёты о доставке

Отчёт — `deliver_sm` с `esm_class` 0x04 на приёмник или трансивер клиента. Стандартный текст:

```
id:<message_id> sub:001 dlvrd:001 submit date:ГГММДДччмм done date:ГГММДДччмм stat:DELIVRD err:000 text:
```

плюс TLV `receipted_message_id` (0x001E) и `message_state` (0x0427). Времена — по UTC.

| Сообщение | `stat` | `err` |
|---|---|---|
| доставлено, прочитано | `DELIVRD` | `000` |
| у получателя нет MAX | `UNDELIV` | `001` |
| аккаунт недоступен | `UNDELIV` | `002` |
| ждало отправки дольше срока | `EXPIRED` | `003` |
| сбой площадки | `UNDELIV` | `004` |

Деньги по не отправленным возвращены (`UNDELIV`, `EXPIRED`). Отчёт по состоянию «ушло, но подтверждения
доставки нет» не отправляется. Текст сообщения в отчёт не входит.

Отчёты берутся из базы раз в 3 секунды, пока у клиента есть вошедший приёмник; отметка «отдан» ставится после
`deliver_sm_resp` с `ESME_ROK`. Не подтвердил или не был на связи — отчёт придёт при следующем входе
(доставка «хотя бы раз»: клиент отбрасывает повторы по `message_id`). Отчёты по сообщениям старше 3 суток
не отдаются. Одновременно в полёте не больше 50 неподтверждённых отчётов на сессию.

## Кабинет клиента

Только свой контур (`/client/*`).

- `GET /client/messages/smpp` → `{ "enabled": true, "connection": { "host", "port", "tls_port" }, "smpp": { "system_id", "enabled", "allowed_ips", "last_bind_at", "created_at" } | null }`.
  `port` и `tls_port` — `null`, если слушатель не включён.
- `POST /client/messages/smpp` → `201`, `{ "smpp": { … }, "password": "…" }`. Пароль — единственный раз.
  `409` — подключение уже создано или продукт выключен.
- `POST /client/messages/smpp/password` → `{ "smpp": { … }, "password": "…" }`: новый пароль, прежний
  перестаёт подходить для новых подключений (открытые сессии доживают до разрыва).
- `PATCH /client/messages/smpp` ← `{ "enabled": false, "allowedIps": ["203.0.113.5"] }` — любое из двух
  полей. Адреса — IPv4/IPv6 по одному, не больше 20; пустой список — «любые».

Создание, смена пароля и изменение пишутся в журнал (`smpp_account.created`, `smpp_account.password_reset`,
`smpp_account.updated`); пароль в журнал не попадает.

## Сотрудникам

- `GET /smpp/accounts` (роли `admin`, `support`) → `{ "accounts": [{ "client_id", "client_name", "system_id", "enabled",
  "allowed_ips", "last_bind_at", "created_at" }] }`. Пароль не отдаётся никому, кроме клиента при создании.
- `PATCH /smpp/accounts/:clientId` (только `admin`) ← `{ "enabled": false }` — отключить подключение клиента (например,
  при подозрении на утечку пароля) или вернуть; пишется в журнал (`smpp_account.updated`). Открытые сессии доживают до
  разрыва, новые входы отклоняются (`ESME_RBINDFAIL`).

В кабинете — «Сообщения MAX» → блок «Подключения клиентов по SMPP».

## Настройка площадки

Переменные окружения API (не процесса воркера): `SMPP_HOST` (по умолчанию `0.0.0.0`), `SMPP_PORT`,
`SMPP_TLS_PORT`, `SMPP_TLS_CERT_FILE`, `SMPP_TLS_KEY_FILE`. Порт `0` — слушатель выключен. Включение и
открытие порта — [deploy/README.md](../../deploy/README.md), «Сервер SMPP».
