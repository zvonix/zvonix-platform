# Контракт: заявки на кабинет

Как участник рынка получает кабинет службы такси или партнёра.
Решение и его обоснование — [ADR-0052](../adr/0052-odin-vkhod-dva-kabineta.md).

Первая заявка подаётся вместе с регистрацией (`POST /auth/register`, [auth.md](auth.md)).
Вторая — из уже открытого кабинета, тем же входом (`POST /me/applications`).
Карточку клиента или партнёра заводит **одобрение** — одной транзакцией с открытием входа,
записью в журнал и письмом заявителю.

## Вид заявки

```json
{ "id": "…", "cabinet": "partner", "status": "submitted",
  "answers": {},
  "created_at": "…", "decided_at": null, "decision_note": null }
```

| `status` | Смысл |
|---|---|
| `submitted` | ждёт решения администратора |
| `approved` | карточка заведена, вход открыт |
| `rejected` | отказано; причина — в `decision_note` и в письме |
| `withdrawn` | заявитель отозвал сам |

Три последних окончательны: новая попытка — новая заявка. Открытая заявка одного вида
у человека одна.

## Очередь администратора

### `GET /applications` — администратор, поддержка

Параметры: `status` (необязательно), `limit` (до 200), `offset`. Новые сверху.

`200` → `{ "applications": [ …вид заявки, "applicant": { "id", "email", "full_name",
"status", "email_confirmed" } ], "total": 12 }`

### `POST /applications/:id/approve` — администратор

```json
{ "displayName": "Партнёр 23" }
```

`displayName` — псевдоним, под которым партнёра увидят клиенты
([ADR-0014](../adr/0014-vybor-partnera-klientom.md)); для партнёра обязателен (`400` без него),
для клиента не нужен.

Одна транзакция: запирается заявка → заводится карточка (клиент — `active` с названием
из анкеты и нулевым разрешённым минусом; партнёр — `pending`, звонки после проверки
оборудования) → учётная запись `pending` становится `active` → заявка `approved` →
журнал `application.approved` и `client.created` / `partner.created` → письмо в очереди.

`200` → `{ "application": … }`.

| Отказ | Когда |
|---|---|
| `404` | заявки нет |
| `409` | решение уже принято; почта заявителя не подтверждена; учётная запись приостановлена или закрыта; у заявителя уже есть такая карточка; псевдоним занят |

Любой отказ откатывает всё: карточки нет, заявка ждёт, вход закрыт.

### `POST /applications/:id/reject` — администратор

```json
{ "note": "В вашем регионе партнёры пока не нужны" }
```

Причина обязательна (3–1000 символов) — она уходит заявителю письмом. Первая заявка:
вход остаётся закрытым. Вторая: кабинет, который уже был, работает дальше.
`409` — решение уже принято.

## Свои заявки

Идентификатор заявителя не принимается нигде — он выводится из сессии.

### `GET /me/applications`

`200` → `{ "applications": [ … ] }`. Сотруднику площадки — пустой список.

### `POST /me/applications`

Тело — `cabinet` и `answers`, как у регистрации ([auth.md](auth.md)).

`201` → `{ "application": … }`.

| Отказ | Когда |
|---|---|
| `403` | спрашивает сотрудник площадки: кабинетов у него не бывает |
| `409` | этот кабинет уже подключён; заявка того же вида уже ждёт решения |

### `POST /me/applications/:id/withdraw`

Отзыв своей заявки, пока по ней не решили. `200`; `404` — чужая или несуществующая
(ответ одинаков, чтобы по нему не перебирались чужие); `409` — решение уже принято.
