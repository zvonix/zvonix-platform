# Контракт: качество терминации и порог отключения

Наблюдение за SIM и шлюзами и автоматическое снятие неисправных с маршрутизации.
Обоснование — [ADR-0027](../adr/0027-porog-otklyucheniya.md).

## Две разные задачи, которые легко перепутать

**Измерить** — ASR и ACD, чтобы человек видел, что происходит у партнёра.
**Отключить неисправное** — автоматически, без человека.

Автомат на ASR **не смотрит**. Доля отвеченных падает, когда клиент звонит по холодной
базе: номера не отвечают, абоненты заняты, кто-то сбрасывает. Отключить за это SIM
партнёра значит наказать его за поведение чужих абонентов.

## Что считается отказом сети

Порог считает вызовы, не состоявшиеся **по причине, не зависящей от вызываемого**:
`status = failed` при пустой причине отказа.

| Что случилось | Статус вызова | Порогом считается |
|---|---|---|
| Не ответил, занято, вызывающий сбросил | `no_answer`, `busy`, `cancelled` | нет — это поведение абонента |
| Сеть отвергла, SIM заблокирована оператором, шлюз не отвечает | `failed`, причина пуста | **да** |
| Не хватило денег, нет тарифа, лимит, узел потерялся | `failed`, причина заполнена | нет — это платформа |

Разделение держится на том, что причину отказа заполняет **только** control plane, когда
отказывает сам. Отказ из телефонии приходит с одним лишь кодом разъединения от узла.

## Окно скользящее

Последние N минут, а не календарные сутки: неисправность не знает о полуночи, и SIM,
отказавшая двадцать раз с 23:50 до 00:10, календарным окном не ловится вовсе.

Этим порог отличается от квот ([limits.md](limits.md)), где окно календарное — потому
что квоту объясняют клиенту, а порог объясняют себе.

## Шлюз проверяется раньше своих SIM

Если заданы оба порога, отказы неисправного шлюза набирают и его SIM: вызовы-то одни
и те же. Поэтому проход сначала отключает шлюзы, а SIM отключённого шлюза в том же
проходе уже не рассматривает — иначе партнёру пришлось бы включать обратно два объекта
вместо одного, хотя виновато железо, а не пластик.

## Что происходит при срабатывании

SIM переводится в `throttled`, шлюз — в `suspended`. Оба состояния снимают объект
с маршрутизации и оба обратимы.

**Обратно включает человек** — через `POST /sim-cards/:id/status` или
`POST /gateways/:id/status`. Автоматического возврата нет намеренно: отключённая SIM
не получает вызовов, её окно опустеет само собой, и возврат «когда отказов не осталось»
превратился бы в мигание — с реальными вызовами клиентов в каждой попытке.

Отключение записывается в журнал аудита **без пользователя-инициатора** и с числом
отказов: на вопрос партнёра «за что» иначе отвечать нечем.

## `GET /quality/sims?windowMinutes=1440&partnerId=…` — роли `admin`, `support`

`200` → `{ "sims": [ { "subject_id", "partner_id", "attempts", "answered", "network_failures", "asr_basis_points", "acd_seconds" } ] }`

Сверху — те, у кого больше отказов сети, не более двухсот строк: разбор читает человек,
а не машина. `windowMinutes` по умолчанию сутки, предел — месяц. `asr_basis_points`
в десятитысячных: `5000` значит 50%.

## `GET /quality/gateways?windowMinutes=…&partnerId=…` — роли `admin`, `support`

То же по шлюзам: неисправным бывает не только пластик, но и железо.

## `PUT /failure-thresholds/:scope` — роль `admin`

`scope` — `sim` или `gateway`. Канала здесь нет: вызовы канала срываются, как правило,
из-за номерной базы клиента, а автоматически отключить платящего клиента — решение
с прямыми последствиями для выручки.

```json
{ "failures": 10, "windowMinutes": 60 }
```

`200` → `{ "threshold": { "scope", "failures", "window_minutes" } }`

`PUT` по области, а не `POST` с идентификатором: порог на область ровно один, и второй
означал бы, что срабатывает прочитанный первым. Порог в один отказ отвергается: один
отказ сети случается и на исправной SIM.

## `GET /failure-thresholds` — роли `admin`, `support`

`200` → `{ "thresholds": [ … ] }`. Пусто — автоматического отключения нет вовсе.

## `DELETE /failure-thresholds/:scope` — роль `admin`

`200` → снятый порог. Уже отключённые объекты в строй не возвращаются: это отдельное
действие человека.
