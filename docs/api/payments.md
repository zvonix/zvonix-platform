# Контракт: платежи клиентов

Заявки на пополнение счёта. Основание — [ADR-0064](../adr/0064-platezhi-karkas.md).

Платёж — **заявка и её исход**. Деньги на счёте появляются только проводкой с ключом
`payment:<идентификатор>` ([billing.md](billing.md)): зачисление и переход заявки в `succeeded`
— одна транзакция, повтор и гонка вторых денег не кладут.

Состояния: `pending` → `succeeded` | `rejected` | `cancelled`. Из `pending` — в одно из
окончательных; назад нельзя.

Вид платежа в ответах:

```json
{
  "id": "…", "client_id": "…", "status": "pending",
  "amount": "1500.5", "received_amount": null,
  "comment": "платёжка 17", "resolution_note": null,
  "created_at": "…", "resolved_at": null
}
```

Суммы — строкой в рублях, как везде.

## Кабинет клиента

### `GET /client/payments` — кабинет `client`

`200` → `{ "instructions": "…", "payments": [ … ] }` — последние 50 заявок клиента и реквизиты
для перевода (настройка `payments.manual_instructions`). Пустые реквизиты — приём заявок закрыт.

### `POST /client/payments` — кабинет `client`

```json
{ "amount": "1500.50", "comment": "платёжка 17" }
```

`201` → `{ "payment": { … }, "instructions": "…" }`.

Отказы: `409` — реквизиты не заданы или уже 5 открытых заявок; `400` — сумма не от 100 до
1 000 000 ₽ или не похожа на деньги.

### `POST /client/payments/:id/cancel` — кабинет `client`

Отзыв своей заявки. `200` → `{ "payment": { … } }`. Повтор отзыва — тот же ответ. Чужая заявка —
`404`, а не `409`: существование не выдаётся. Уже решённая (зачислена, отклонена) — `409`.

## Администратор и поддержка

### `GET /payments` — роли `admin`, `support`

Параметры: `status`, `clientId`, `limit` (до 200), `offset`. `200` → `{ "payments": [ … ], "total" }`,
новые первыми.

### `POST /payments/:id/confirm` — роль `admin`

```json
{ "amount": "950.25" }
```

`amount` — сколько пришло на самом деле; не названо — столько, сколько просил клиент (в пределах
до 1 000 000 ₽). `200` → `{ "payment": { … } }` со `status: "succeeded"`, `received_amount`.

Повтор безопасен: уже зачисленная заявка возвращается как есть, деньги второй раз не кладутся.
Отклонённую или отозванную подтвердить нельзя — `409`. Попадает в журнал (`payment.confirmed`,
состояние до и после) и в книгу проводкой `deposit` с ключом `payment:<id>`.

### `POST /payments/:id/reject` — роль `admin`

```json
{ "reason": "перевод не поступил" }
```

Причина (3–300 знаков) видна клиенту. `200` → `{ "payment": { … } }`. Уже решённая заявка — `409`;
повтор отказа — тот же ответ. Журнал: `payment.rejected`.

Поддержка заявки **видит**, но подтверждать и отклонять не может (`403`): зачисление — деньги,
как и ручное пополнение.
