# Контракт: тарифы и наценка платформы

Цена партнёра, правила тарификации и наценка платформы.
Обоснование — [ADR-0010](../adr/0010-model-billinga.md).

## Направление — это оператор и регион, а не префикс

[DOMAIN.md](../DOMAIN.md) описывал направление как «префикс → оператор/регион».
Так делать нельзя: [ADR-0013](../adr/0013-opredelenie-operatora.md) запрещает определять
оператора по префиксу, потому что из-за переносимости номеров это **неверный оператор**,
а неверный оператор — платный звонок с денег партнёра. Тариф, привязанный к префиксу,
воспроизвёл бы ровно ту ошибку, ради недопущения которой существует резолвер.

Поэтому направление берётся из ответа `OperatorResolver`: **оператор и регион**.
Префикс в тарификации не участвует вовсе. Сущность `Destination` отменена — тарифы
ссылаются на оператора и регион напрямую.

## Как считается стоимость

```
оплачиваемые секунды = минимум, если разговор короче
                       иначе минимум + шаги до покрытия остатка
цена партнёра        = плата за соединение + цена за минуту × секунды / 60
наценка платформы    = фикс + процент от цены партнёра
цена клиента         = цена партнёра + наценка
```

**Минимальная длительность — это первый оплачиваемый период целиком**, а не нижняя граница
округления. При минимуме 45 секунд и шаге 30 разговор в 50 секунд стоит 45 + 30 = 75 секунд,
а не 60. Так тарифицируют операторы; другой порядок даёт систематическую ошибку в пользу
одной из сторон на каждом коротком вызове.

**Несостоявшийся вызов не стоит ничего** — включая плату за соединение и фиксированную
часть наценки: услуга не оказана, брать не с чего.

**Умножение выполняется до деления.** Цена за минуту умножается на секунды и только потом
делится на шестьдесят: обратный порядок теряет точность на каждом вызове.

**Округление — часть тарифа, а не свойство кода** (ADR-0010). Задаётся у каждой цены
партнёра: `half_away_from_zero` (по умолчанию) или `toward_zero`. Округление выполняется
ровно один раз — при переводе цены за минуту в цену за фактическую длительность.

Все суммы — целое число микроединиц (1 ₽ = 1 000 000) и передаются **строкой**:
JSON-число потеряло бы копейки молча.

## Записи не редактируются

У каждой записи есть момент начала действия. Действует та, у которой он наибольший
из уже наступивших. Даты окончания нет намеренно.

Изменить цену значит **добавить новую запись**, а не поправить старую. Тогда история цен
остаётся целой, а звонок, тарифицированный вчера, не переоценивается сегодняшней ценой —
это инвариант [DOMAIN.md](../DOMAIN.md).

**Частный случай побеждает общий, независимо от свежести.** Тариф с указанным регионом
выигрывает у тарифа без региона; правило наценки для конкретного клиента выигрывает
у правила платформы. Обратный порядок означал бы, что новая общая цена молча отменяет
договорённость по региону или с клиентом.

## `POST /partner-rates` — роль `admin`

```json
{
  "partnerId": "…",
  "operatorId": "…",
  "region": "Москва",
  "pricePerMinute": "1.20",
  "billingIncrementSeconds": 30,
  "minimumDurationSeconds": 45,
  "connectionFee": "0.50",
  "rounding": "half_away_from_zero",
  "effectiveFrom": "2026-09-02T00:00:00.000Z"
}
```

`201` → `{ "rate": { … } }`

`region` пусто — тариф на любой регион. `effectiveFrom` пусто — действует с этого момента.
`billingIncrementSeconds` по умолчанию 1, то есть посекундная тарификация.

## `GET /partner-rates?partnerId=…` — роли `admin`, `support`

`200` → `{ "rates": [ … ] }`, свежие сверху. Видна вся история цен партнёра.

## `POST /commission-rules` — роль `admin`

```json
{ "clientId": "…", "fixedFee": "0.50", "percentBasisPoints": 1500, "effectiveFrom": "…" }
```

`201` → `{ "rule": { … } }`

`clientId` пусто — правило платформы по умолчанию, применяется ко всем, у кого нет своего.

`percentBasisPoints` — доля в десятитысячных: 15% = 1500. Значение выше 10 000 отвергается:
наценка больше ста процентов — это опечатка в разрядах, а не коммерческое решение,
и поймать её лучше при вставке, чем при счёте.

Фикс и процент применяются **вместе**, а не по выбору: фикс покрывает стоимость самого
факта вызова, процент — долю от объёма.

## `GET /commission-rules` — роли `admin`, `support`

`200` → `{ "rules": [ … ] }`, свежие сверху.

## `POST /tariffs/price` — роли `admin`, `support`

```json
{
  "partnerId": "…", "clientId": "…", "operatorId": "…", "region": "Москва",
  "durationSeconds": 137, "at": "2026-08-01T00:00:00.000Z"
}
```

`200` → `{ "billed_seconds", "partner_amount", "commission_amount", "client_amount",
"rate_id", "commission_rule_id" }`

Отвечает на два вопроса, которые задают постоянно: «почему списали столько» и «сколько
будет стоить». По коду тарификации на них отвечать неудобно, по логам — невозможно.

`at` — момент, на который берутся правила; по умолчанию сейчас. Задаётся явно, потому что
тарификация CDR выполняется позже звонка, иногда сильно позже: узел мог держать CDR
на диске, пока control plane был недоступен.

`rate_id` и `commission_rule_id` в ответе — чтобы в споре было видно **какая именно** запись
применилась, а не только результат.

## Отсутствие тарифа — отказ

Нет действующей цены партнёра по направлению или нет правила наценки — `404`.

Это не «бесплатный звонок»: вызов без цены означает, что платформа не знает, сколько он
стоит партнёру. Списать нечего, начислить нечего, а минуты своей SIM партнёр тратит.
