# Контракт: токен GitHub для обновлений

Основание — [ADR-0084](../adr/0084-token-github-v-nastroykah.md). Только роль `admin`. Состояние читается из каталога
обмена службы обновления ([updates.md](updates.md)), токен передаётся ей заявкой: API токен не хранит и назад не отдаёт.

## `GET /updates/github-token`

```json
{
  "available": true,
  "state": "ok",
  "repository": "zvonix/zvonix-platform",
  "checked_at": "2026-10-14T07:00:00+00:00",
  "expires_at": "2026-12-31T12:00:00+00:00",
  "days_left": 78,
  "problem": null,
  "busy": false,
  "last_run": { "id": "…", "status": "succeeded", "finished_at": "…" }
}
```

`state`: `ok`; `soon` — осталось 14 суток и меньше; `invalid` — GitHub токен не принял или срок истёк
(`problem` — причина по-русски); `unknown` — служба ещё не проверяла токен (`available: false`).
`expires_at` пуст у классического токена без срока. `busy` — заявка с токеном ждёт или проверяется.
В ответе **нет** самого токена и быть не может.

## `POST /updates/github-token`

Тело `{ "token": "github_pat_…" }` — буквы, цифры и подчёркивание, 20–255 знаков. Ответ `202` →
`{ "request": { "id", "action": "token-set", "tag": null, "by", "requested_at" } }`. Токен в ответе не возвращается.

| Код | Когда |
|---|---|
| `400` | токен негодной формы |
| `403` | не администратор |
| `409` | предыдущая заявка с токеном ещё ждёт или проверяется; обновление из кабинета не настроено |

Служба проверяет токен у GitHub по репозиторию из своего файла и только потом записывает его. Результат —
в `GET /updates/github-token` (`state`, `problem`, `last_run.status`) и в журнале обновлений
(действие «Токен GitHub»; токена в журнале нет). Журнал действий хранит факт заявки (`update.token-set_requested`),
без токена.
