# Контракты API

Здесь лежат спецификации внешних контрактов: OpenAPI для клиентского API,
описание вебхуков и формат обмена с узлами АТС.

Правило: контракт описывается **до** реализации и обновляется в том же изменении,
что и код. Клиенты (службы такси) интегрируются по этим файлам, поэтому расхождение
спецификации с поведением — не документационный, а продуктовый дефект.

## Общее для всех контрактов

**Изменяющее обращение ограничено по частоте** ([ADR-0041](../adr/0041-predel-chastoty-izmeneniy.md)):
учётной записи разрешено 120 изменений в минуту, дальше — `429` с заголовком `Retry-After`
и кодом `rate_limited`. Считаются `POST`, `PUT`, `PATCH` и `DELETE` от человека.

Не считаются: чтения; узел АТС (его объём это телефония); публичные пути входа
и регистрации, у которых свои пределы по адресу источника; выход и закрытие своей сессии.

**Клиентский ключ — исключение из исключения:** он считается, и чтения тоже
([ADR-0044](../adr/0044-klientskiy-api.md), [client-api.md](client-api.md)). Узел развернули
мы, чужую диспетчерскую — нет, и сорвавшийся там цикл опроса остановит только человек. Предел вспомогательный: при недоступном Redis обращение проходит, потому что
настоящие рубежи — роль, владение и журнал — стоят в PostgreSQL.

## Описано

- [auth.md](auth.md) — вход в кабинеты: регистрация, вход, сессии, права администратора,
  проверки состояния. Обоснование решений — [ADR-0018](../adr/0018-autentifikaciya.md).
- [applications.md](applications.md) — заявки на кабинет клиента или партнёра: очередь
  администратора, одобрение, отказ, вторая заявка из кабинета. Обоснование —
  [ADR-0052](../adr/0052-odin-vkhod-dva-kabineta.md).
- [operators.md](operators.md) — справочник операторов и определение оператора номера.
  Обоснование — [ADR-0013](../adr/0013-opredelenie-operatora.md).
- [billing.md](billing.md) — клиенты, партнёры, счета, журнал проводок, пополнение
  баланса. Обоснование — [ADR-0010](../adr/0010-model-billinga.md).
- [tariffs.md](tariffs.md) — цены партнёров, правила тарификации и наценка платформы.
  Обоснование — [ADR-0010](../adr/0010-model-billinga.md).
- [machine-keys.md](machine-keys.md) — выпуск и отзыв ключей узлов и клиентских
  интеграций. Обоснование — [ADR-0019](../adr/0019-dostup-mashin.md).
- [nodes.md](nodes.md) — реестр узлов АТС: заведение, команда установки, регистрация,
  heartbeat, вывод из эксплуатации. Обоснование —
  [ADR-0009](../adr/0009-programmnaya-ats.md).
- [telephony.md](telephony.md) — шлюзы партнёров, **SIP-транки**, каналы клиентов и каталог SIP,
  который узел получает из control plane. Обоснование —
  [ADR-0009](../adr/0009-programmnaya-ats.md).
- [client.md](client.md) — кабинет клиента: свой счёт, свои линии, свои вызовы.
  Граница контура — [ADR-0014](../adr/0014-vybor-partnera-klientom.md): партнёра клиент
  не видит ни в каком виде, а причина отказа приходит переведённой.
- [client-api.md](client-api.md) — **машинный контур клиента `/v1`**: состояние вызовов
  и остаток на счёте по ключу. Обязательство о совместимости и предел частоты, считающий
  и чтения, — [ADR-0044](../adr/0044-klientskiy-api.md).
- [partner.md](partner.md) — кабинет партнёра: свой заработок, своё оборудование,
  свои цены и вызовы через своё железо. Граница та же, что у клиента, но с другой
  стороны: клиента партнёр не видит, а пароль провайдера не покидает узел.
- [routing.md](routing.md) — решение по вызову: шлюз, SIM, резерв средств; там же
  разбор «почему не звонит» — список вызовов, сводка причин отказа и проверка маршрута.
  Обоснование — [ARCHITECTURE.md](../ARCHITECTURE.md) и [ADR-0010](../adr/0010-model-billinga.md).
- [recordings.md](recordings.md) — записи разговоров: выгрузка узлом, подписанные ссылки,
  срок хранения. Основание — правило о персональных данных в [CLAUDE.md](../../CLAUDE.md).
- [payments.md](payments.md) — пополнение счёта: заявка клиента, реквизиты, подтверждение или отказ
  администратором; зачисление ровно один раз. Основание — [ADR-0064](../adr/0064-platezhi-karkas.md).
- [messaging.md](messaging.md) — сообщения MAX: аккаунты партнёров, вход по QR, цена и лимиты.
- [smpp.md](smpp.md) — подключение клиента по SMPP: вход, `submit_sm`, отчёты о доставке.
  Основание — [ADR-0071](../adr/0071-soobscheniya-max.md).
- [servers.md](servers.md) — состояние серверов: нагрузка, память, диск площадки и узлов, история,
  сроки хранения. Основание — [ADR-0065](../adr/0065-sostoyanie-serverov-i-istoriya.md).
- [node.md](node.md) — узел АТС → control plane: учётные записи SIP, запрос маршрута
  на каждый вызов, CDR, регистрация узла, heartbeat. Обоснование —
  [ADR-0009](../adr/0009-programmnaya-ats.md) и [ADR-0019](../adr/0019-dostup-mashin.md).
  Согласован; обработчики появляются по мере готовности модулей.

## Осталось описать, в порядке необходимости

1. **Клиентский API** — инициация вызова, статус, получение записи, баланс.
   Доступ по API-ключу, а не по сессии: схема доступа задана
   в [ADR-0019](../adr/0019-dostup-mashin.md), состав обработчиков — нет.
2. **Вебхуки клиенту** — завершение вызова, низкий баланс, исчерпание лимита.
   Подпись HMAC: здесь она возможна, потому что запрос формируем мы.
