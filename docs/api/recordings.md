# Контракт: записи разговоров

Выгрузка записи узлом и выдача её человеку.
Основание — [ARCHITECTURE.md](../ARCHITECTURE.md) и правило из
[CLAUDE.md](../../CLAUDE.md): записи разговоров — персональные данные, и хранятся они
только в объектном хранилище, с подписанными ссылками и аудитом обращений.

## Как запись попадает в хранилище

**Узел не получает ключей хранилища никогда.** Они дают доступ ко всем записям всех
клиентов, и скомпрометированный узел читал бы чужие разговоры. Вместо ключей узел
получает подписанную ссылку ровно на один объект и на короткий срок.

Файл идёт **напрямую в хранилище, минуя control plane**: тот не пропускает через себя
медиа (ARCHITECTURE.md), и гонять через него сотни мегабайт записей значило бы
превратить его в узкое место на ровном месте.

```
Узел  →  POST /node/recordings/upload-url   →  подписанная ссылка + ключ объекта
Узел  →  PUT <ссылка>                        →  хранилище (мимо control plane)
Узел  →  POST /node/recordings/uploaded      →  запись считается завершённой
```

**Ключ объекта задаёт control plane**, а не узел: иначе скомпрометированный узел прислал бы
ключ чужой записи и затёр её. Вид ключа — `recordings/<год>/<месяц>/<вызов>.wav`; разбиение
по месяцам нужно не хранилищу, а человеку, которому иначе пришлось бы смотреть плоский
каталог с миллионом объектов.

Узел выгружает записи **только своих вызовов**: вызов помнит, какой узел его обслуживал.

## Срок хранения

`RECORDING_RETENTION_DAYS`, по умолчанию 90 суток. Считается от начала вызова при выдаче
ссылки на выгрузку — срок хранения, зависящий от момента уборки, это отсутствие срока.

По истечении **сначала удаляется объект, потом ставится отметка в базе**. Обратный порядок
оставлял бы при сбое запись, помеченную удалённой, а файл — на месте: разговор продолжал бы
храниться, и никто бы об этом не знал.

Строка в базе остаётся и после удаления: по ней видно, что запись была и ушла по сроку.

## `POST /node/recordings/upload-url` — ключ узла

```json
{ "callId": "…" }
```

`200` → `{ "upload_url", "object_key", "expires_at" }`

Повторный запрос по тому же вызову возвращает **ту же** запись с новой ссылкой: первая
попытка выгрузки могла не дойти, и это штатный режим, а не вторая запись.

Чужой вызов — `403`. Уже выгруженная запись — `409`.

## `POST /node/recordings/uploaded` — ключ узла

```json
{ "callId": "…", "durationSeconds": 137, "sizeBytes": 1048576 }
```

`200` → `{ "recording_id", "uploaded_at" }`

До этого отчёта запись считается незавершённой и не отдаётся никому: ссылка на выгрузку
могла быть выдана, а файл не доехать, и предлагать человеку слушать пустоту незачем.

`sizeBytes` обязан быть больше нуля: пустой файл — это несостоявшаяся запись, и принимать
его за состоявшуюся значит потом не найти разговор, который считался сохранённым.

Повторный отчёт **не переписывает момент первой выгрузки**: по нему считается, сколько
запись уже хранится.

## `POST /recordings/:id/link` — роли `admin`, `support`, `client`

`201` → `{ "url", "expires_at" }`

Подписанная ссылка на прослушивание. Живёт `RECORDING_LINK_TTL_SECONDS`, по умолчанию
пятнадцать минут: ссылка даёт доступ к разговору без всякой дальнейшей проверки прав,
поэтому пересланная в мессенджере она должна протухнуть раньше, чем её откроют посторонние.

**`POST`, а не `GET`, намеренно:** обращение меняет состояние — оно попадает в журнал
аудита. По `GET` журнал засорился бы обращениями, которых никто не совершал:
предзагрузкой браузера, перезагрузкой страницы, обходчиком.

**Каждая выдача ссылки попадает в журнал** — с тем, кто попросил, откуда и когда. Это
единственный след того, кто получил доступ к разговору. Сама ссылка в журнал не пишется:
она даёт доступ, а журнал читают шире, чем имеют право слушать.

Роль — только первый рубеж. Клиент получает ссылку лишь на записи своих вызовов; владение
проверяет сервис ([ADR-0018](../adr/0018-autentifikaciya.md)). Чужая запись отвечает `404`,
а не `403`: иначе по разнице ответов проверяется её существование.

### Партнёр — по объявлению либо по разовому доступу

Обоснование — [ADR-0036](../adr/0036-dostup-partnyora-k-zapisyam.md). У партнёра два
независимых основания, и оба касаются **только его собственных вызовов** — тех, что
обслужила его SIM. Чужая запись отвечает `404`.

**Объявленное намерение.** Партнёр включает себе доступ сам и слышит тогда все свои
вызовы. Умолчание — выключено: тот, кто ничего не сказал, записей не получает.

**Разовый доступ.** Администратор открывает доступ к **одной записи** на ограниченный
срок и с обязательной причиной. Работает независимо от объявления и нужен для разбора
спора «моя SIM исправна, дело не в ней».

Отдавать партнёру разговор пассажира — передача персональных данных третьему лицу,
и отменить состоявшееся прослушивание нельзя. Поэтому оба пути требуют явного действия,
каждое обращение попадает в журнал, а **оферта клиента обязана содержать его
подтверждение**, что согласие абонентов получено: субъект данных — пассажир, а не служба
такси. Юридическая часть — за владельцем ([ADR-0011](../adr/0011-pravovoy-kontur.md)).

### `PUT /partners/:id/recordings-access` — роли `partner`, `admin`

```json
{ "listens": true }
```

`200` → `{ "partner": { "id", "listens_to_recordings" } }`

Партнёр меняет только своё: роль — первый рубеж, владение проверяет служба
([ADR-0018](../adr/0018-autentifikaciya.md)). Чужой партнёр — `404`.

Признак сразу виден клиентам в `GET /partner-aliases`, и клиент, которому это не подходит,
такого партнёра в приоритеты канала не поставит. **Цена решения:** попросивший записи
получит меньше трафика. Это осознанный выбор — партнёры решают сами.

### `POST /recordings/:id/grant` — роль `admin`

```json
{ "reason": "Обращение №17: партнёр оспаривает тарификацию", "hours": 24 }
```

`201` → `{ "grant": { "partner_id", "reason", "expires_at" } }`

**Партнёр в запросе не называется** — он выводится из вызова, чью SIM тот обслужил.
Назвать его руками значит однажды назвать не того и выдать чужой разговор.

Причина обязательна: доступ к персональным данным без причины не выдаётся. Срок —
от часа до недели, по умолчанию сутки: доступ, который не истекает, перестаёт быть
разовым. У вызова нет SIM — `409`: открывать доступ некому.

### `DELETE /recordings/:id/grant` — роль `admin`

`200` → `{ "revoked": <сколько погашено> }`

Гасит все действующие доступы к записи. Строки не удаляются — они часть следа.

### `GET /recordings/:id/grants` — роли `admin`, `support`

`200` → `{ "grants": [{ "partner_id", "reason", "expires_at", "revoked_at", "created_at" }] }`

Кому открывали эту запись. Отдаются и погашенные, и истёкшие: это след, а не список
действующих прав. Вопрос «кто слушал разговор» разбирается по нему и по журналу действий.

## `GET /recordings/by-call/:callId` — роли `admin`, `support`

`200` → `{ "recording": { … } | null }`

Есть ли запись у вызова и в каком она состоянии. Отдельно от ссылки: узнать, что запись
есть, — не то же самое, что её послушать, и второе требует следа в журнале, а первое нет.

## Что не проверено на живом хранилище

MinIO под рукой не было. Проверено против подставного сервера S3 — то есть настоящим
клиентом, с настоящей подписью, адресацией путём и учётными данными, но не против
настоящего MinIO.

Не подтверждено: поведение при выгрузке файла по подписанной ссылке (это делает узел,
control plane в ней не участвует), политики корзины и срок жизни подписи на стороне
хранилища.
