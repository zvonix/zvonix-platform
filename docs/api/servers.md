# Контракт: состояние серверов

Нагрузка, память и диск площадки и узлов, история и срок её хранения.
Основание — [ADR-0065](../adr/0065-sostoyanie-serverov-i-istoriya.md).

## `GET /servers` — роли `admin`, `support`

Только чтение. Параметр `range`: `hour` (по умолчанию — `day`), `day`, `week`; иное — `400`.

`200` →

```json
{
  "servers": [
    {
      "scope": "platform", "id": null, "name": "Площадка", "status": null, "stale": false,
      "current": {
        "load1": 1.25, "cpu_cores": 4,
        "mem_total_mb": 8192, "mem_available_mb": 5400,
        "disk_total_mb": 102400, "disk_free_mb": 61000,
        "active_calls": null, "taken_at": "2026-10-03T09:30:00.000Z"
      },
      "series": [
        { "at": "2026-10-03T09:25:00.000Z", "load1": 1.1, "mem_available_mb": 5300, "disk_free_mb": 61000 }
      ]
    }
  ]
}
```

Первой идёт сама площадка (`scope: "platform"`), затем узлы (`scope: "node"`, `status` —
состояние узла); выведенные из эксплуатации не показываются. `current` пуст, пока замеров не было;
`stale: true` — последнего замера нет или он старше 15 минут.

`series` — история, сжатая на стороне базы в корзины: час — по минуте, сутки — по 5 минут, неделя —
по 30. В корзине нагрузка **усреднена**, а память и диск взяты по **худшему** значению (наименьшему
свободному): график, на котором провал сгладился бы, соврал бы. Пустые корзины пропускаются —
разрыв между точками клиент рисует разрывом линии.

## `POST /node/metrics` — ключ узла

Замер от узла, раз в 30–60 секунд (скрипт пульса, `node/install.sh`). Тело:

```json
{ "load1": 1.25, "cpuCores": 4, "memTotalMb": 8000, "memAvailableMb": 6000,
  "diskTotalMb": 100000, "diskFreeMb": 60000, "activeCalls": 2 }
```

`activeCalls` необязательно. Свободное не больше всего: большее приводится к объёму. Неправдоподобное
(отрицательное, нет ядер, не число) — `400`. Человеческая сессия этот обработчик не открывает, ключ
узла не открывает `GET /servers`. `204` без тела.

Узел, у которого скрипт пульса старый, замеры просто не присылает: на странице у него «замеров нет».

## Откуда замеры площадки

Задача воркера `servers.sample` раз в минуту: нагрузка и память операционной системы, диск каталога
записей (`RECORDINGS_DIR`; нет такого каталога — диск, на котором работает процесс).

## Хранение

История убирается задачей `servers.purge-history` раз в час: старше `retention.metrics_days`
(по умолчанию 14 суток, от 1 до 90). Срок записей разговоров — `retention.recordings_days`
(по умолчанию 30, от 1 до 3650), действует на записи, принятые после изменения.
Значения вне пределов отвергаются при сохранении настройки (`400`). См. [settings.md](settings.md).

## Тревога о диске

Свободного места меньше 10 % по свежему замеру площадки или узла — письмо администраторам
([ADR-0062](../adr/0062-trevogi-administratoram.md)), повтор по источнику раз в 12 часов.
