# Контракт: кабинет партнёра

Что партнёр видит и делает сам. Обоснование границы —
[ADR-0014](../adr/0014-vybor-partnera-klientom.md) (стороны не видят друг друга),
[ADR-0018](../adr/0018-autentifikaciya.md) (доступ),
[ADR-0036](../adr/0036-dostup-partnyora-k-zapisyam.md) (записи),
[ADR-0039](../adr/0039-terminaciya-cherez-sip-trank.md) (транки),
[ADR-0040](../adr/0040-poryadok-terminacii-predlozhenie-i-cena.md) (цена и порядок).

## Откуда берётся партнёр

**Из сессии, и только из неё** — как и в [кабинете клиента](client.md). Ни один
обработчик раздела не принимает идентификатор партнёра: административные пути
начинаются с него (`/partners/:id/…`), и открыть их роли `partner` значило бы разрешить
подставить чужой.

**Кабинет открывает владение карточкой партнёра, а не роль**
([ADR-0052](../adr/0052-odin-vkhod-dva-kabineta.md)). Учётная запись без неё получает
`403` с текстом «Кабинет партнёра не подключён»: это незавершённое подключение,
и человек обязан увидеть, что ему нужна заявка ([applications.md](applications.md)).

У сотрудников площадки свои пути, где партнёр назван явно. Вызовы клиента, которым
владеет тот же человек, на SIM и транки этого партнёра не уходят никогда.

## Чего здесь нет

**Клиента — ни в каком виде.** В вызове партнёра нет ни клиента, ни его линии, ни цены,
которую тот заплатил. Через чьё железо ушёл вызов — дело партнёра; кто его заказал —
не его дело. Это обратная сторона [ADR-0014](../adr/0014-vybor-partnera-klientom.md),
и работает она симметрично.

**Пароля провайдера.** У SIP-транка отдаются адрес, способ доступа и имя учётной записи;
пароль зашифрован и уходит **только узлу**, в его конфигурацию. Восстановить его
из API невозможно ни партнёру, ни администратору.

**Кнопок заводить SIP-транк.** Транк привязывается к узлу площадки, а узлы — не дело
партнёра: выбирать ему нечем. Транки по-прежнему заводит администратор.

Шлюзы, порты и SIM партнёр заводит **сам**
([ADR-0043](../adr/0043-partnyor-zavodit-svoyo-oborudovanie.md)): никто, кроме него,
не знает ни модели GOIP, ни номера карты в третьем порту. Цену он назначает тоже сам —
но только по направлению, где площадка **открыла коридор**; см. `POST /partner/rates`.

## `GET /partner/account`

`200` →

```json
{
  "partner": {
    "id": "…", "name": "Иванов Иван Иванович", "display_name": "Партнёр 17",
    "status": "verified", "listens_to_recordings": false, "created_at": "…"
  },
  "funds": { "balance": "1284.75" }
}
```

Состояние здесь есть намеренно: **партнёр работает только в `verified`**, и `pending`
объясняет, почему через его железо не идёт ни один вызов. Без этой строки человек ищет
причину в оборудовании.

Псевдоним рядом с именем — под ним партнёра видит клиент, и в разговоре с площадкой речь
идёт именно о нём.

Один остаток без «доступно»: резервы и разрешённый минус — устройство клиентского счёта.
Остаток здесь означает «заработано, к выплате»; выплаты появятся на шестом этапе
и будут уменьшать его проводкой.

## `GET /partner/entries?limit=100&offset=0`

`200` → `{ "entries": [ … ], "balance": "1284.75", "total": 42 }`

Тот же вид проводки, что у администратора и у клиента: видно, **за что** начислено.
Основной сценарий — сверка наших чисел со счётом своего оператора. Потолок страницы — 200.

## `GET /partner/equipment`

`200` →

```json
{
  "gateways": [
    {
      "id": "…", "name": "GOIP в гараже", "type": "goip", "status": "active", "suspended_by": null,
      "model": null, "sip_username": "gw-a1b2c3d4e5f6", "on_node": true, "registered_at": "…",
      "ports": [
        { "id": "…", "port_number": 1, "state": "idle",
          "sim": { "id": "…", "msisdn": "79001234567", "status": "active",
                   "operator_id": "…", "operator_name": "ПАО «МегаФон»",
                   "network_scope": "own_network", "max_concurrent_calls": 2,
                   "operator_confirmed_at": "…" } }
      ]
    }
  ],
  "connection": { "server": "sip.zvonix.com", "port": 5060 },
  "trunks": [
    { "id": "…", "name": "Транк у провайдера", "status": "active",
      "proxy_host": "sip.provider.ru", "registers_outbound": true,
      "outbound_username": "zvonix-17", "max_concurrent_calls": 30, "on_node": true }
  ],
  "spare_sims": [ { "id": "…", "msisdn": "79007654321", … } ]
}
```

Одним ответом, а не тремя обращениями: шлюз без портов и порт без SIM по отдельности
не значат ничего, и собирать эту картину в браузере значило бы показывать её по частям,
каждую со своей ошибкой загрузки.

**`on_node` — есть ли регистрация на узле.** Ключевое поле раздела: без регистрации вызов
на шлюз не уйдёт вовсе — диалплан набирает его как зарегистрированного пользователя,
и отбор кандидатов сужается узлом, приславшим запрос
([routing.md](routing.md), отказ `gateway_unregistered`). Это единственная неисправность,
которую может починить **только партнёр**, и до появления раздела она была видна лишь нам.

У транка `on_node` означает другое — назначен ли узел, который поднимает регистрацию
у провайдера: к транку регистрируемся мы, а не он к нам.

**`connection` и `sip_username` — куда и под каким именем регистрировать устройство.**
Сервер — `SIP_REALM`, порт — `sip-port` профиля узла (`node/conf/autoload_configs/sofia.conf.xml`).
Имя не секрет и отдаётся всегда: оно нужно при каждой перенастройке устройства, а раньше
было видно только в минуту заведения. Пароль не отдаётся никогда — только при выдаче.

`spare_sims` — карты, не стоящие ни в одном порту. Заведённая, но не вставленная ёмкость
не видна больше нигде: в списке шлюзов её нет по определению.

Транк в `gateways` не попадает, хотя в базе это тоже шлюз: портов и SIM у него нет,
а есть адрес провайдера.

**Приговора «почему через меня не идут вызовы» здесь нет.** Отдаются факты; вывод
складывается из них вместе с состоянием партнёра (`GET /partner/account`) и наличием
цены (`GET /partner/rates`). Считать его на сервере значило бы завести второе описание
условий отбора рядом с запросом `findSimCandidates` — и разойтись с ним на первой правке.

## `GET /partner/rates`

`200` →

```json
{
  "reference_call_seconds": 60,
  "rates": [
    { "id": "…", "operator_id": "…", "operator_name": "ПАО «МегаФон»", "region": null,
      "termination_kind": "sim", "price_per_minute": "2", "connection_fee": "0",
      "billing_increment_seconds": 1, "minimum_duration_seconds": 0,
      "rounding": "half_away_from_zero", "effective_from": "…",
      "reference_cost": "2", "band": { "min_price": "1", "max_price": "5" },
      "within_band": true }
  ],
  "operators_without_price": [ { "operator_id": "…", "operator_name": "ООО «Т2 Мобайл»" } ],
  "open_directions": [
    { "operator_id": "…", "operator_name": "ООО «Т2 Мобайл»",
      "min_price": "1", "max_price": "4" }
  ]
}
```

Только **действующие** цены — по одной на направление. Направление это оператор, регион
**и способ терминации**: у партнёра с SIM и транком по одному оператору две разные цены,
и сводить их в строку было бы неправдой
([ADR-0040](../adr/0040-poryadok-terminacii-predlozhenie-i-cena.md)).

`reference_cost` — стоимость эталонного вызова по этому тарифу. Именно она сравнивается
с коридором, а не цена за минуту: тариф это пять чисел, и коридор, ограничивающий одно
из них, обходится платой за соединение ([ADR-0023](../adr/0023-koridory-cen.md)).

`band` пуст, когда коридора по направлению нет; тогда `within_band` истинно —
«ограничения нет» значит «цена в него укладывается».

`operators_without_price` — операторы, по которым у партнёра нет ни одной цены.
Кандидат без действующей цены в перебор **не попадает вовсе** (отказ `no_tariff`),
то есть каждая строка здесь — ёмкость, которая не получит ни одного вызова. Для партнёра
это самый дорогой из невидимых отказов. Неподтверждённые операторы сюда не попадают:
по ним вызов не совершается ни у кого
([ADR-0032](../adr/0032-zagruzka-plana-numeracii.md)).

`open_directions` — направления, **открытые площадкой**, вместе с рамками. Чего в этом
списке нет, того назначить нельзя: коридор задаёт площадка. Сказать это до отправки формы
честнее, чем отказом после.

Отдельным списком, а не полем при цене, по двум причинам. Рамки нужны и там, где цена
уже есть, — её тоже меняют. И у цены стоит **её собственный** коридор, который
у региональной цены может быть региональным; показывать его как рамки для новой цены
«на любой регион» значило бы назвать не те границы. Здесь всегда общий коридор — тот,
что применится, если региональный не задан. Задан свой по региону — он строже, и точные
числа придут в отказе.

## `POST /partner/rates`

Тело: `operatorId`, `terminationKind` (**обязателен**), `region?`, `pricePerMinute`,
`billingIncrementSeconds`, `minimumDurationSeconds`, `connectionFee?`, `rounding?`.
`201` → `{ "rate": { … } }` — та же строка цены, что отдаёт административный
`POST /partner-rates`.

Первое, что партнёр в этой площадке меняет сам.

**Партнёра в теле нет** — он из сессии. **Момента начала действия нет тоже**, и это
не упрощение: коридор проверяется тем, что действовал на этот момент, и, приняв дату
от партнёра, площадка дала бы ему выбрать время, когда коридор был шире, — то есть
обойти ограничение, ради которого он заведён. Цена партнёра действует **с этого момента**.
Лишние поля в теле отбрасываются схемой, а не принимаются.

**Направление без коридора отвергается** (`validation_failed`). Это условие пересмотра,
названное в [ADR-0023](../adr/0023-koridory-cen.md) прямо: «коридора нет — ограничения
нет» верно ровно до того дня, когда цену назначает не тот, кто коридор задаёт. Отказ
несёт в `details` направление и строку `remedy`: коридор открывает площадка, и без неё
отказ читается как ошибка самого партнёра. Администратору тот же запрет **не ставится** —
иначе новое направление невозможно открыть, ведь коридор задаёт он же.

Цена вне коридора отвергается с числами: `reference_cost` — стоимость эталонного вызова
по присланному тарифу, `min_price` и `max_price` — границы. Именно стоимость вызова,
а не цена за минуту: коридор по одному числу из пяти обходится платой за соединение.

Строка не редактируется, добавляется новая: история цен остаётся целой, а вызов,
тарифицированный вчера, сегодняшней ценой не переоценивается. Закрытый партнёр
получает `permission_denied`.

Проверка коридора и вставка идут **одной транзакцией** с запиранием направлений
оператора: иначе между ними коридор успевал сузиться, и цена оказывалась снаружи
ограничения, которое её только что пропустило.

## `GET /partner/calls?from=…&to=…&status=…&limit=…&offset=…`

`200` → `{ "calls": [ … ], "total": 342 }`

```json
{
  "id": "…", "destination": "79001234567", "status": "completed",
  "sim_card_id": "…", "gateway_id": "…", "operator_id": "…",
  "duration_seconds": 62, "started_at": "…"
}
```

Вызовы, прошедшие через железо партнёра, — по ним он сверяется со счётом своего
оператора. Роли `admin` и `support` тот же обработчик отдаёт вызовы названного
в `partnerId` партнёра; партнёру — только свои, независимо от параметров.

Страницами и за период, как списки клиента: `from` и `to` включительно, свежие сверху,
`total` — число всех подходящих вызовов, а не размер страницы. Без `limit` отдаются
двести последних — так обработчик отвечал до появления страниц. Отбора по клиенту
и линии нет: стороны друг друга не видят.

Названия шлюзов и номера SIM берутся из `GET /partner/equipment`: второй список имён
разъехался бы с первым.

## `POST /calls/:id/wrong-network`

`200` → `{ "invalidated": true, "destination": "79001234567" }`

«Этот вызов ушёл не в мою сеть». Отменяет определение оператора для номера немедленно,
не дожидаясь срока годности записи: партнёр видит счёт своего оператора и знает
об ошибке раньше нас — у него это деньги, у нас строка в базе
([ADR-0013](../adr/0013-opredelenie-operatora.md)).

Обращение привязано к **вызову**, а не к номеру: по номеру можно было бы отменять
определение чего угодно. Чужой и несуществующий вызов отвечают одинаково.

Не больше 50 обращений в час на партнёра. Ограничение не про добросовестность:
каждая отмена отправляет номер на повторное определение, а внешний источник держит два
запроса в секунду **на всю платформу**, и партнёр с ошибкой в своей выгрузке оставил бы
без определения чужие вызовы.

## `PUT /partners/:id/recordings-access`

Тело: `{ "listens": true }`. Идентификатор в адресе здесь есть, потому что обработчик
общий с административным; владение проверяет служба, чужой партнёр отвечает `404`.

Партнёр объявляет, слушает ли он записи разговоров через своё оборудование
([ADR-0036](../adr/0036-dostup-partnyora-k-zapisyam.md)). Признак сразу виден клиентам
в списке псевдонимов, и клиент, которому это не подходит, поставит такого партнёра ниже.
Цена решения названа в ADR: попросивший записи получит меньше трафика.

## Партнёр заводит оборудование

Все обработчики этого раздела берут партнёра **из сессии**. Чужой объект отвечает `404`,
а не `403`: партнёр не должен узнавать даже того, что объект существует
([ADR-0043](../adr/0043-partnyor-zavodit-svoyo-oborudovanie.md)). **Свой SIP-транк — тоже
`404`**: он лежит рядом со шлюзами, но заводит и настраивает его площадка, и пути шлюзов
к нему не относятся ([ADR-0047](../adr/0047-kto-vyklyuchil-shlyuz.md)).

**Количество ограничено.** `PARTNER_GATEWAY_LIMIT` и `PARTNER_SIM_LIMIT` (по умолчанию 50
и 1000) задают, сколько шлюзов и карт партнёр держит одновременно; списанное не считается.
Предел не против злого умысла, а против того, что объём больше не ограничен человеком,
печатающим руками. Превышение — `409` с числом в `details.limit`.

### `POST /partner/gateways`

`{ "name": "GOIP в офисе", "type": "goip", "model": "GoIP-8", "portCount": 8 }`

`type` — только `goip` или `android`. `sip_trunk` отвергается: см. выше.

`201` → `{ "gateway": …, "account": { "username": "gw-…", "password": "…", "realm": "…" } }`

**Пароль отдаётся один раз и больше ниоткуда не читается** — в базе лежит хеш. Он приходит
туда же, где партнёр его и вводит, настраивая оборудование; пока шлюз заводил
администратор, пароль обязан был дойти до партнёра перепиской.

Шлюз создаётся в состоянии `pending`: учётная запись выдана, но каталог узла её
не отдаёт, пока шлюз не включён.

### `POST /partner/gateways/:id/status`

`active` — включить, `suspended` — выключить, `retired` — списать.

**Кто выключил, решает, кто вправе вернуть** ([ADR-0047](../adr/0047-kto-vyklyuchil-shlyuz.md)).
В ответе `GET /partner/equipment` у шлюза есть `suspended_by`: `partner` — выключили вы,
`platform` — отключила площадка, `failure_threshold` — отключён автоматически за отказы
сети (проверьте оборудование). Кто именно на площадке выключил, не раскрывается.

| Сейчас | Можно | Ответ на остальное |
|---|---|---|
| `pending` | `active`, `retired` | `suspended` — `409`: выключать нечего |
| `active` | `suspended`, `retired` | — |
| `suspended`, `partner` | `active`, `retired` | — |
| `suspended`, `platform` или `failure_threshold` | — | `409`, в `details.remedy` — что делать |
| `retired` | — | `409` |

Повтор уже выполненного перехода — `active` у включённого, `suspended` у выключенного
вами — `201` без изменений; у списанного и отключённого площадкой повтор, как и любой
запрос, — `409` по таблице. Если состояние успели изменить между чтением и записью
(например, площадка заперла шлюз), ответ — `409` «состояние шлюза успело измениться».

**Списывает партнёр сам:** железо у него, и когда оно уехало, знает об этом он.
Списание необратимо — в кабинете оно идёт через окно подтверждения с числом вынимаемых карт.

**Списание освобождает порты шлюза**: карты из них вынимаются той же транзакцией
и становятся свободными. Порта после списания не существует, и держать в нём нечего;
кабинет называет число карт прямо в вопросе о подтверждении. Обратное — поставить карту
в порт списанного шлюза — отвечает `409`. Установка, пришедшая одновременно со списанием,
дожидается его и получает тот же `409` ([ADR-0048](../adr/0048-poryadok-blokirovok-portov.md)).

Отключённым площадкой или порогом шлюзом партнёр не распоряжается вовсе — ни включить,
ни списать, ответ `409`. Первое понятно, второе не сразу: «списал — завёл новый» это тот же
обход отключения, только длиннее. Своё же выключение он снимает сам.

### `POST /partner/gateways/:id/credentials`

Перевыпуск учётных данных. Меняются **и имя, и пароль**: имя уже засветилось в записи
регистрации и в логах узла, а перенастраивать оборудование всё равно придётся.

### `POST /partner/gateways/:id/ports`

`{ "portNumber": 3 }` — номер порта, как он подписан на корпусе устройства, или
`{ "count": 4 }` — столько портов следующими номерами. Ответ — `{ "port", "ports" }`,
как у административного пути ([telephony.md](telephony.md)). Порты 1…`portCount`
появляются уже при `POST /partner/gateways`.

У списанного шлюза порт не завести — `409`.

### `POST /partner/sim-cards`

`{ "msisdn": "+7 913 042-41-23" }` — кабинет оператора не спрашивает: его называет
резолвер по номеру, а без подтверждённого источника — владелец диапазона, и карта
остаётся неподтверждённой ([telephony.md](telephony.md), `POST /sim-cards`). Номера нет
и в плане нумерации — `503` «Не удалось определить оператора номера». `operatorId`
принимается по-прежнему и тогда сверяется.

Номер приводится к каноническому виду: `8913…`, `+7 913 …` и `7913…` — одно и то же.

**Оператор сверяется с источником по самому номеру карты**
([ADR-0013](../adr/0013-opredelenie-operatora.md)), и расхождение — отказ, а не
предупреждение. Причина не в недоверии к партнёру, а в его же деньгах: у всех партнёров
тариф «безлимит внутри своей сети», и карта, заявленная одним оператором, а на деле
принадлежащая другому, превращает бесплатный вызов в платный за его счёт.

Карта создаётся в состоянии `new` — вызовов она не получает.

### `POST /partner/sim-cards/:id/status`

`{ "status": "active" }` — включить, `{ "status": "retired" }` — списать.
Одна дверь на оба действия намеренно: две — это два места, где однажды разойдутся
проверки владения.

**Включение** проходит только с подтверждённым оператором. Подтверждённое при заведении
не переспрашивается; источник дёргается лишь тогда, когда при заведении он промолчал, —
это единственный способ повторить попытку, не заводя карту заново. Молчит он и сейчас —
отказ проверки; включить карту тогда может администратор.

**Придержанную карту** (`throttled` — порог отказов сети или решение администратора)
партнёр не включает и не списывает: `409`, распоряжается ею администратор. Номер карты,
которую площадка придержала или заблокировала, тот же партнёр заново не заведёт —
`POST /partner/sim-cards` отвечает `409`: иначе «списал — завёл заново» обходил бы решение. Сама она тоже не возвращается:
включённая, пока старые отказы ещё в окне, она отключилась бы на следующем проходе
([ADR-0047](../adr/0047-kto-vyklyuchil-shlyuz.md)).

**Вторая запись того же номера** не включается, пока площадка держит номер на другой записи
этого партнёра, — `409` с тем же текстом, что и при заведении: карта за номером одна
([ADR-0047](../adr/0047-kto-vyklyuchil-shlyuz.md), «Ревизия»).

**Решение площадки, принятое во время запроса, не затирается.** Придержала карту, пока
партнёр её включал, — `409` «Состояние карты успело измениться — обновите страницу»; пока
списывал — `409` по новому состоянию ([ADR-0048](../adr/0048-poryadok-blokirovok-portov.md)).

**Списание** возможно только у карты **вне порта**: стоящую в порту сначала выньте
(`POST /partner/gateway-ports/:id/sim` с `null`). Молча вынуть за партнёра было бы
удобно ровно один раз и непонятно во все остальные, когда карта исчезла из порта сама.

Заблокированной площадкой картой партнёр не распоряжается — `409`.

### `POST /partner/gateway-ports/:id/sim`

`{ "simCardId": "…" }` — вставить карту в порт, `{ "simCardId": null }` — вынуть.

И порт, и карта обязаны принадлежать партнёру: чужую карту в свой порт не вставить.
Списанную — тоже: `409`, в порту она ожила бы для маршрутизации.
