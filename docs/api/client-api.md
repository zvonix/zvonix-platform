# Клиентский API — `/v1`

Машинный контур службы такси: диспетчерская система спрашивает состояние вызовов
и остаток на счёте. Решение — [ADR-0044](../adr/0044-klientskiy-api.md).

Не путать с [client.md](client.md): там **кабинет**, который открывает человек сессией.
Здесь — контракт для чужой программы, и обязательства у него другие.

## Совместимость

**В пределах `/v1` изменения только добавляющие.** Поле может появиться, но не исчезнуть
и не поменять смысл. Новое значение перечисления — тоже ломающее изменение: чужой разбор
его не ждёт. Понадобится сломать — появится `/v2`, и оба будут работать одновременно.

Кабинет такого обязательства не несёт: он уезжает вместе с приложением. Поэтому пути
разные, хотя данные за ними одни и те же.

## Доступ

Ключ вида `client_api` ([ADR-0019](../adr/0019-dostup-mashin.md)), схема **Basic**:
имя пользователя — идентификатор ключа `zvx_client_…`, пароль — секрет.

```
curl -u 'zvx_client_a1b2c3d4e5f6:<секрет>' https://cp.example.com/v1/balance
```

Клиент **выводится из ключа**: его идентификатор нигде не принимается, подставить чужой
нечего. Сессией человека `/v1` не открывается — `401`; ключом узла тоже.

Ключи клиент заводит себе сам, в кабинете: [client.md](client.md), раздел
«Ключи API». Секрет показывается один раз.

## Предел частоты

**`CLIENT_API_RATE_LIMIT_PER_MINUTE` обращений в минуту на один ключ**, по умолчанию 600.
Считаются и чтения — в отличие от людей: здесь опрос и есть основная нагрузка, и предел,
не считающий его, не держал бы ничего.

Превышение — `429`, код `rate_limited`, заголовок `Retry-After`, а в `details.key_id`
назван ключ: у клиента их несколько, и разбирать он будет тот, который сорвался.

Счёт по ключу, а не по клиенту: сорвавшаяся одна система не останавливает остальные.

## Что видно, а что нет

Ровно то же, что в кабинете, и по тем же правилам
([ADR-0014](../adr/0014-vybor-partnera-klientom.md)): **ни партнёра, ни шлюза, ни SIM,
ни псевдонима** — ни в одном поле. Причина отказа приходит переведённой: всё, что
не про самого клиента, схлопывается в `platform`, иначе по внутренним причинам читалась бы
ёмкость площадки.

## `GET /v1/calls`

Вызовы клиента. Отбор: `status`, `channelId`, `destination`, `from`, `to`, `limit`,
`offset` — те же, что в кабинете.

`200` →

```json
{
  "total": 128,
  "calls": [
    {
      "id": "…",
      "destination": "79161234567",
      "status": "completed",
      "failure_reason": null,
      "duration_seconds": 42,
      "started_at": "2026-09-09T09:00:00.000Z",
      "answered_at": "2026-09-09T09:00:06.000Z",
      "ended_at": "2026-09-09T09:00:48.000Z",
      "region": "Москва",
      "channel": { "id": "…", "name": "Основная линия" },
      "operator": { "id": "…", "name": "МТС" }
    }
  ]
}
```

Пока нет вебхуков, **это и есть способ узнать о завершении вызова**. Предел частоты
рассчитан на опрос: раз в секунду с запасом на параллельные обращения.

## `GET /v1/calls/:id`

Один вызов. `200` → `{ "call": { … } }` в том же виде.

Чужой — `404`: отбор идёт вместе с клиентом из ключа, поэтому чужой вызов
не находится, а не «находится и скрывается».

## `GET /v1/balance`

Сколько можно потратить. Заодно освобождает просроченные резервы: зависший из-за
потерянного CDR резерв иначе тихо съедает доступное, и машина увидит «денег нет» там,
где они есть.

`200` →

```json
{
  "client": { "id": "…", "name": "Такси Пример", "status": "active" },
  "funds": {
    "balance": "12000.500000",
    "overdraft_limit": "0.000000",
    "held": "120.000000",
    "available": "11880.500000"
  }
}
```

Суммы — строки с точкой, в рублях с шестью знаками ([ADR-0010](../adr/0010-model-billinga.md)).
Состояние клиента здесь намеренно: `suspended` объясняет, почему не идут вызовы, и без
него причину ищут в своей АТС.

Движения по счёту в `/v1` нет: это разбор, а разбирают люди в кабинете. Отдавать машине
историю списаний значит обязаться держать её формат годами ради сценария, которого нет.

## `POST /v1/messages`, `GET /v1/messages`, `GET /v1/messages/:id` — сообщения MAX

Отправка текстовых сообщений в мессенджер MAX тем же ключом ([messaging.md](messaging.md),
[ADR-0071](../adr/0071-soobscheniya-max.md)). Тело отправки: `{ "to": "79001234567", "text": "…",
"externalId": "…" }`; `externalId` — ваш ключ повтора: тот же ключ возвращает прежнее сообщение, деньги
не списываются дважды. `201` → `{ "message": { … } }` в состоянии `queued`; статус меняется на `sent`,
`delivered`, `read` либо `failed` (причина — `failure_reason`, деньги при этом возвращены). Отказы: `400` —
номер или текст негодны, `409` — не хватает денег или ключ уже занят другим сообщением, `503` — нет
доступных аккаунтов. Ни провайдера, ни партнёра в ответах нет.

## Чего ещё нет

**Инициации вызова.** Сегодня вызов приходит от софтфона клиента; поставить его самим —
значит звать `originate` через ESL, то есть завести новый путь в media plane. Это отдельное
решение, и оно не принимается заодно с контуром доступа.

**Вебхуков.** Доставка чужому серверу — это очередь, повторы, подпись и мёртвые письма,
то есть отдельная работа с собственными отказами. Полработы вебхуков хуже честного опроса.

**Выдачи записи разговора.** Механизм подписанных ссылок готов
([recordings.md](recordings.md)), но кому и на каких условиях отдавать запись машине —
вопрос персональных данных, а не контракта.
