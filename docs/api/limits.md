# Контракт: лимиты по окнам

Квоты клиента, канала, партнёра и SIM. Обоснование — [ADR-0026](../adr/0026-limity-po-oknam.md),
пояс окон и лимит денег — [ADR-0102](../adr/0102-chasovoy-poyas-akkaunta-i-limity.md).

## Зачем они

Это в первую очередь **защита SIM партнёра**, и только во вторую — ограничение клиента.
Оператор блокирует SIM за нечеловеческий профиль трафика, а потерянная SIM означает
потерянного партнёра ([BACKLOG.md](../BACKLOG.md)).

## Что и как считается

Лимит принадлежит **ровно одному** субъекту: клиенту, каналу, партнёру или SIM.
Лимит без субъекта не относится ни к кому, а лимит на двоих сразу непонятно кого
ограничивает — и то и другое отвергается.

| Поле | Значения |
|------|----------|
| `window` | `minute`, `hour`, `day`, `week` (с понедельника), `month` — **календарные, в поясе владельца** (`timezone`) |
| `metric` | `calls` — попытки вызова; `minutes` — разговор; `money` — расход клиента на звонки, **только у клиента и канала** |
| `value` | Сколько звонков, минут или рублей допустимо за окно. Ноль отвергается: «звонить нельзя вовсе» — это состояние субъекта, а не лимит |
| `per_sim` | Только у лимита партнёра: одно правило, **свой счётчик у каждой его SIM** ([ADR-0057](../adr/0057-limity-partnyora.md)). Исчерпание закрывает только ту карту |
| `rounding` | Только у `minutes`: `second` — как есть, `minute` — каждый разговор округляется вверх до целой минуты, как считает пакет оператора |
| `period_start_day` | Только у `month`: день обновления окна, 1–28; пусто — первое число |
| `set_by` | `platform`, `partner` или `client`. Партнёр и клиент меняют только свои; одинаковые правила площадки и владельца действуют оба |
| `timezone` | Пояс, в котором считаются окна: копия пояса владельца — клиента для клиента и канала, партнёра для партнёра, SIM и тарифа. Правила до ADR-0102 и аккаунты без выбранного пояса — `UTC`. Меняется только сменой пояса аккаунта (`PUT /client/account/timezone`, `PUT /partner/account/timezone`): набранное за текущее окно переносится в окно по новому поясу, берётся большее |

**Окно фиксированное, а не скользящее.** Видно, когда счётчик обнулится: в местную полночь владельца,
в понедельник, первого числа. Скользящее окно потребовало бы хранить отметку каждого
вызова — таблицу, растущую с трафиком.

**Часовой пояс — владельца** ([ADR-0102](../adr/0102-chasovoy-poyas-akkaunta-i-limity.md)): сутки клиента из Новосибирска начинаются
в полночь по Новосибирску, с переходами на летнее время в других странах. «Сутки» без указания пояса — спор,
поэтому пояс назван у каждого правила.

**Звонки считаются штуками, минуты — секундами, рубли — микроединицами.** Разговор в 90 секунд — это не «полторы
минуты» и не «одна», а ровно девяносто. Поэтому в ответе `used` и `limit` даны
в единицах хранения: у метрики `minutes` предел в 10 минут выглядит как `limit: 600`, у `money` предел
в 300 ₽ — `limit: 300000000`.

**Счётчики коротких окон** (минута, час) хранятся двое суток, остальные — квартал:
минутные окна за квартал дали бы миллионы строк.

## Когда счётчик растёт

- `calls` — в момент создания вызова, **той же транзакцией**. Вызова нет — счётчика тоже;
- `minutes` и `money` — при тарификации CDR, той же транзакцией, что и деньги; `money` — ровно сумма списания
  клиента. Повторная доставка CDR их не удваивает: проводки второй раз тоже не будет.

**Квота по минутам и деньгам может быть перебрана на один вызов.** Минуты
становятся известны только по CDR, а начатый разговор не отменяется. Резервировать
минуты вперёд не имеет смысла: квота нужна, чтобы профиль трафика SIM не выглядел
машинным, а не чтобы не пустить кого-то в последнюю минуту.

## Изменение и удаление

**Изменение предела не трогает израсходованное:** квота изменилась, потраченное никуда
не делось. **Удаление лимита уносит его счётчики** — это и есть способ обнулить счёт.

---

## `POST /limits` — роль `admin`

```json
{ "clientId": "…", "window": "day", "metric": "calls", "value": 500 }
```

Вместо `clientId` может быть `channelId`, `partnerId` или `simCardId` — ровно один.
Необязательные: `perSim` (только с `partnerId`), `rounding` (только у `minutes`),
`periodStartDay` (только у `month`). Несогласованное сочетание — `400` с причиной.

`201` → `{ "limit": { "id", "client_id", "channel_id", "partner_id", "sim_card_id", "window", "metric", "value", "timezone", … } }`

Пояс правилу ставит площадка — пояс владельца субъекта; принять его в запросе нельзя. `money` у партнёра и SIM — `400`.

Ни одного субъекта или больше одного — `400`. Второй лимит с тем же окном и метрикой
у того же субъекта — `409`: два одинаковых означали бы, что предел зависит от того,
какую строку прочитали первой.

## `GET /limits?clientId=…&channelId=…&partnerId=…&simCardId=…` — роли `admin`, `support`

`200` → `{ "limits": [ { …лимит…, "usage_sim_card_id", "bucket_start", "resets_at", "used", "limit", "exceeded" } ] }`

У лимита «на каждую карту» строк столько, сколько карт уже звонили в окне,
`usage_sim_card_id` называет карту. `resets_at` — когда окно закончится.

Без параметров — все лимиты платформы. `used` и `limit` — в единицах хранения,
`bucket_start` — начало текущего окна (момент UTC; окно — в `timezone`). С этого ответа начинается разбор
«почему у клиента не звонит».

## `PUT /limits/:id` — роль `admin`

```json
{ "value": 1000, "rounding": "minute", "periodStartDay": 15 }
```

`rounding` и `periodStartDay` — необязательны. `200` → `{ "limit": { … } }`. Счётчик
не трогается.

## `DELETE /limits/:id` — роль `admin`

`200` → `{ "limit": { … } }` — снятый лимит. Вместе с ним удаляются его счётчики.

## Отказ по лимиту

Причина `limit_exceeded`, код SIP `503 Service Unavailable` ([node.md](node.md)).
Отличается от `no_sim_available` намеренно: «все партнёры исчерпали квоту» и «SIM нет
вовсе» — разные разговоры с партнёром.

## Лимиты партнёра — `/partner/limits`, кабинет партнёра

Партнёр сам задаёт себе лимиты ([ADR-0057](../adr/0057-limity-partnyora.md)): это защита
его карт от блокировки оператором. Подробно — [partner.md](partner.md), «Лимиты». С [ADR-0080](../adr/0080-edinye-limity-i-raspredelenie.md)
лимит звонков заводится в тарифе партнёра (`limit_rules.tariff_id`) и действует на каждую карту этого тарифа.
