# Контракт: реестр узлов АТС

Заведение узла, установка, heartbeat и вывод из эксплуатации.
Решения — [ADR-0009](../adr/0009-programmnaya-ats.md) (FreeSWITCH)
и [ADR-0019](../adr/0019-dostup-mashin.md) (доступ машин).
Обмен узла с control plane по каждому вызову — в [node.md](node.md).

## Порядок подключения

Узел заводится **до** установки. Так задано в [ARCHITECTURE.md](../ARCHITECTURE.md)
и отражено в первом состоянии жизненного цикла — `provisioned`: запись есть, машина
ещё не отвечает.

```
Админ создаёт узел  →  POST /nodes                      status = provisioned
                       ← команда установки (токен на час)
Скрипт на сервере   →  POST /node/enroll                status = installing
                       ← постоянный ключ + адреса обработчиков
Агент               →  POST /node/heartbeat  (раз в 30 с) status = online | degraded
Молчание > 90 с     →                                    status = offline
Админ закрывает     →  POST /nodes/:id/decommission     status = decommissioned
```

Обратный порядок — «токен, а узел создастся сам» — позволял бы зарегистрировать узел,
которого никто не заводил.

## Состояния

| Состояние | Что означает | Маршрутизируется |
|-----------|--------------|------------------|
| `provisioned` | Запись заведена, установка не начиналась | нет |
| `installing` | Токен применён, узел получил ключ и настраивается | нет |
| `online` | Присылает heartbeat | **да** |
| `degraded` | Отвечает, но сам объявил себя ослабленным | **да** |
| `offline` | Молчит дольше порога | нет |
| `decommissioned` | Выведен навсегда, ключи отозваны | нет |

**Решение «жив или нет» принимает control plane, а не узел.** Молчание дольше порога
снимает узел с маршрутизации независимо от того, что он присылал раньше: узел, потерявший
связь, о своей недоступности сообщить не может по определению.

Порог — три пропущенных heartbeat, а не один: одна потерянная посылка не должна снимать
узел с маршрутизации, три подряд — уже должны.

## `POST /nodes` — роль `admin`

```json
{ "name": "Москва-1", "sipAddress": "sip.msk1.example.com", "allowedIps": ["203.0.113.7"] }
```

`201` →
```json
{
  "node": { "id", "name", "hostname", "sip_address", "status", "agent_version",
            "active_calls", "last_heartbeat_at", "created_at" },
  "install": { "command": "curl -fsSL https://…/install.sh | sudo bash -s -- zvx_enroll_…",
               "token_expires_at": "…" }
}
```

`sipAddress` — адрес, на который партнёры направляют свои GOIP. Он **публичный**
и попадает в инструкцию партнёру, поэтому это не тот адрес, с которого узел сам
обращается к control plane.

`allowedIps` ограничивает, откуда принимается **токен установки**. Если адрес будущего
сервера известен заранее — заполнить: токен живёт час, но ограничение закрывает и этот час.

Адрес в команде берётся из `PUBLIC_BASE_URL`, а не из `APP_HOST`: там адрес, который
слушает процесс, и за обратным прокси это `127.0.0.1` — узел обратился бы сам к себе.

Имя узла уникально. Повтор — `409`.

## `POST /nodes/:id/install-command` — роль `admin`

`201` → тот же вид ответа.

Новая команда для уже заведённого узла: у токена срок час, а установка откладывается
на завтра чаще, чем хотелось бы. Прежний токен при этом не отзывается — он истечёт сам.

Выведенному из эксплуатации узлу — `409`.

## `GET /install.sh` — публичный

Скрипт установки, собранный под эту площадку
([ADR-0045](../adr/0045-ustanovshchik-uzla.md)). Это тот адрес, который называет команда
из `POST /nodes/:id/install-command`.

`200` → `text/x-shellscript; charset=utf-8`, `cache-control: no-store`.

Публичный намеренно: секретов в скрипте нет — токен передаётся аргументом команды,
а ключ узла появляется только на самом узле. Закрывать раздачу было бы нечем: `curl`
на чистой машине ещё ничем не располагает.

Control plane подставляет свой адрес и параметры репозитория пакетов, а затем **вкладывает
внутрь шаблоны конфигурации** `node/conf/*.xml`. Скрипт после этого ничего не читает
с диска: у него нет шага, на котором он может оказаться без своих файлов. Подстановки
`@@KEY_ID@@` и `@@KEY_SECRET@@` остаются нетронутыми — их заполняет сам скрипт на узле,
потому что до обмена токена ключа не существует.

**Незаданный `NODE_PACKAGE_REPO_URL` не мешает скрипту отдаться.** Репозиторий нужен
только затем, чтобы **поставить** FreeSWITCH, а стоит он на машине уже или нет — видно
только там ([ADR-0045](../adr/0045-ustanovshchik-uzla.md), «Ревизия»). Скрипт разбирается
на месте: ставить нечего — репозиторий не спрашивает вовсе; есть что — останавливается
и называет переменную, причём **до** обмена одноразового токена.

## `POST /node/enroll` — токен установки

Вызывает скрипт установки. **Единственный обработчик, принимающий токен установки**;
рабочим ключом этот токен не является и никуда больше не проходит.

```json
{ "hostname": "node-msk-1", "agentVersion": "1.0.0" }
```

`200` →
```json
{
  "node": { "id", "name", "hostname", "status": "installing" },
  "key": { "key_id": "zvx_node_…", "secret": "…" },
  "endpoints": { "directory": "…", "dialplan": "…", "cdr": "…", "heartbeat": "…" }
}
```

**Секрет постоянного ключа возвращается здесь** — другого способа передать его на узел нет.
Токен при этом расходуется: повторный вызов той же командой даёт `409` и запись в аудит
`machine_key.enrollment_reused`.

Одноразовость обеспечивает условное обновление в базе, а не проверка перед записью: два
одновременных запуска скрипта иначе оба прошли бы проверку, и рабочие ключи одного узла
получили бы две машины.

**Выданный ключ ограничен адресом, с которого узел пришёл.** Адрес в этот момент известен
точно, а ограничение по адресу — единственная мера, работающая и против кражи ключа
с самого узла.

`hostname` дальше сверяется с полем `hostname` в запросах маршрута ([node.md](node.md)):
расхождение означает, что ключ применён не на том узле, для которого выпущен. Имя
уникально между узлами — два узла с одним именем не дали бы достоверно отнести запрос
маршрута к узлу.

## `POST /node/heartbeat` — ключ узла

```json
{ "activeCalls": 3, "degraded": false, "agentVersion": "1.0.1" }
```

`200` → `{ "status": "online", "next_heartbeat_in_ms": 30000 }`

Интервал приходит **от control plane**: иначе изменение порога требовало бы раскатки
конфигурации на все узлы.

`degraded` узел выставляет сам — часть шлюзов не зарегистрирована, нагрузка выше порога.
Вызовы на него по-прежнему идут: ослабленный узел лучше отсутствующего.

## `GET /nodes` · `GET /nodes/:id` — роли `admin`, `support`

`200` → `{ "nodes": [ … ] }`

Список заодно снимает с маршрутизации замолчавшие узлы: пока нет фоновой задачи,
иначе в панели висел бы `online` у машины, выключенной неделю назад.

Поддержке доступ на чтение нужен: разбор «почему у клиента не звонит» начинается
со списка узлов.

## `POST /nodes/:id/decommission` — роль `admin`

`201` → `{ "node": { …, "status": "decommissioned" } }`

Отзывает **все** ключи узла и закрывает запись. Оставить узел закрытым, а ключи
действующими значит оставить работающий доступ у машины, которой больше нет.

Не `DELETE`, потому что удаления и не происходит: на узел ссылаются CDR,
а их не удаляют никогда.
