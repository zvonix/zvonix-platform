## Что это

Площадка терминации исходящих голосовых вызовов через GSM-шлюзы.
**Клиенты** (службы такси) звонят, вызов уходит на шлюз одного из **партнёров**
(физлица с SIM и GOIP), с баланса клиента списывается стоимость, партнёр получает долю,
платформа — комиссию. Админ задаёт коридоры цен, комиссию и лимиты.

Внимание к терминам: **канал** — это линия клиента, **порт шлюза** — слот с SIM у партнёра.
Смешивать нельзя, см. [docs/GLOSSARY.md](docs/GLOSSARY.md).

## Стек

Полностью TypeScript ([ADR-0008](docs/adr/0008-stek.md)). Монорепозиторий на pnpm workspaces.

- Рантайм: Node.js 22 LTS · TypeScript 5 в строгом режиме · pnpm
- Бэкенд: NestJS · zod для схем, общих с фронтендом
- Фронтенд: Next.js (App Router) · TanStack Query · shadcn/ui
- Данные: PostgreSQL 16 · Drizzle ORM + drizzle-kit · Redis 7 · MinIO (записи)
- Фоновые задачи: BullMQ
- Телефония: FreeSWITCH ([ADR-0009](docs/adr/0009-programmnaya-ats.md)), `mod_xml_curl` за маршрутом, ESL для событий
- Android-приложение партнёра: Kotlin
- Разработка: **WSL2 / Ubuntu 24.04**. Прод: **Ubuntu**. См. [ADR-0007](docs/adr/0007-lokalnaya-sreda.md).

## Команды

Запускать из корня монорепозитория.

| Задача            | Команда |
|-------------------|---------|
| Установить зависимости | `pnpm install` |
| Собрать всё            | `pnpm build` — только то, что уезжает в артефакт (`tsconfig.build.json`) |
| Запустить API локально | `pnpm dev` — `tsc --watch` плюс `node --watch` над собранным кодом |
| Запустить воркер локально | `pnpm worker` — фоновые задачи ([ADR-0020](docs/adr/0020-fonovye-zadachi.md)), нужен Redis |
| Запустить кабинет локально | `pnpm web` — Next на 3000, `/api/*` проксируется в API. Заходить по `localhost`, не по `127.0.0.1` |
| Собрать кабинет | `pnpm web:build` — заодно проверяет его типы |
| Тесты (модульные)      | `pnpm test` |
| Тесты с базой          | `pnpm test:integration` — нужна живая PostgreSQL, адрес в `TEST_DATABASE_URL` |
| Кабинет в браузере      | `pnpm e2e` — Playwright: поднимает API и кабинет за общим прокси, **сбрасывает тестовую базу**. Браузер ставится `pnpm exec playwright install chromium` |
| Линтер                 | `pnpm lint` |
| Проверка типов         | `pnpm typecheck` — весь код, включая тесты; заодно собирает `dist` |
| Форматирование         | `pnpm format` |
| Мёртвый код            | `pnpm deadcode` — knip: неиспользуемые файлы, экспорты и зависимости |
| Ссылки в документации  | `node scripts/docs-links.mjs` — битые цели и несовпадение регистра |
| Конфигурация узла      | `node scripts/node-config.mjs` — XML в `node/`, синтаксис `install.sh` |
| **Полная проверка**    | `pnpm verify` (то же — `pnpm check`, `bash scripts/check.sh`). Тот же скрипт гоняет CI |
| Сгенерировать миграцию | `pnpm db:generate` — **после `pnpm build`**: читается собранная схема |
| Применить миграции     | `pnpm db:migrate` |
| Завести администратора или поддержку | `ADMIN_EMAIL=… ADMIN_PASSWORD=… [ADMIN_ROLE=support] pnpm admin:create` (после `pnpm build`) |
| Разрешить список номеров | `pnpm numbers:resolve <файл> [отчёт.csv]` — замер доли перенесённых |
| Загрузить план нумерации | `pnpm numbering-plan:load` — сейчас, не дожидаясь воркера (после `pnpm build`) |
| Сверить написания операторов | `pnpm operators:aliases [N]` — что план зовёт так, а источник иначе |

Полная проверка — четырнадцать шагов: формат, ссылки в документации, конфигурация узла,
линтер, типы, мёртвый код, соответствие миграций схеме, модульные тесты, тесты с базой,
**сборка кабинета**, **смоук собранного приложения**, **смоук воркера**,
**кабинет в настоящем браузере** и аудит зависимостей.
Типы кабинета проверяет его же сборка: `next build` сам порождает объявления маршрутов,
без которых отдельный `tsc` падает на чистом клоне.
Смоук поднимает `dist` на свободном порту и ходит по настоящему сокету: остальные шаги
могут быть зелёными у приложения, которое не запускается вовсе. Смоук воркера отдельно
проверяет, что процесс гаснет по сигналу и **падает при недоступном Redis, а не висит**.

Шаг «Кабинет в браузере» поднимает API и собранный кабинет **за общим обратным прокси**,
как в проде, и открывает их настоящим Chromium: сессия живёт в cookie на источник,
и кабинет на чужом порту её не отправит. Отвечает на то, чего не видит ни один другой
шаг, — **оживает ли страница**. Шаг **сбрасывает тестовую базу**, поэтому идёт последним
из содержательных. Без установленного браузера — «НЕ ВЫПОЛНЕН», а не провал.

У шага три исхода, а не два. `НЕ ВЫПОЛНЕН` (нет сети, нет базы) не считается успехом
и печатается отдельным списком: «проверка не запускалась» и «ошибок нет» — разные
утверждения. Упавший шаг называет **код возврата** и **свободную память, замеренную
перед его запуском**: тяжёлый шаг умеет умирать молча, и без этих двух чисел провал
не отличить ни от нехватки памяти, ни от снятого процесса. Первое же применение
опровергло записанную до того причину ([TASKS.md](TASKS.md), «Нестабильность сквозных
тестов»).

**Собирается не всё, что проверяется.** `pnpm build` идёт по `tsconfig.build.json` —
шесть пакетов приложения. Тестовый код проверяется отдельным проектом
`tsconfig.tests.json` и в `dist` не попадает ([ADR-0017](docs/adr/0017-sborka-paketov-monorepozitoriya.md),
раздел «Ревизия»). Кэш сборки лежит **внутри `dist`**: снести каталог — значит
пересобрать, а не получить пустоту.

**Приложение запускается только собранным.** `tsx` и esbuild не генерируют метаданные
декораторов, без которых не собирается контейнер зависимостей NestJS
([ADR-0017](docs/adr/0017-sborka-paketov-monorepozitoriya.md)). Тесты работают, потому что
интеграционный набор транспилируется через SWC.

Локальные PostgreSQL 16 и Redis 7 вместе с командами их запуска —
в [ADR-0007](docs/adr/0007-lokalnaya-sreda.md), раздел «Ревизия». Тестам и смоуку нужны обе:
адреса задают `TEST_DATABASE_URL` и `TEST_REDIS_URL`. **Обе не переживают перезагрузку
машины** — служб из них не делали, поэтому после перезапуска их поднимают руками теми же
командами. Признак: сквозные тесты падают на `drop schema`, смоук воркера — на Redis.

Скачивание плана нумерации требует `NODE_OPTIONS=--use-system-ca` **и** корневого
сертификата Минцифры в системном хранилище: источник подписан национальным удостоверяющим
центром, которого нет ни во встроенном списке Node, ни в `ca-certificates` Ubuntu.
Проверке капчи флаг не нужен — у неё обычная цепочка. Подробности — там же, в «Ревизии»,
и в [ADR-0032](docs/adr/0032-zagruzka-plana-numeracii.md).

## Структура

```
apps/
  api/     — NestJS: HTTP API, маршрутизация, доменные модули
  web/     — Next.js: админка, кабинеты клиента и партнёра. Сессия в cookie (ADR-0037),
             общий источник с API за обратным прокси. Свой .env.example
  worker/  — BullMQ: расписание фоновых задач (ADR-0020) — резервы, зависшие вызовы,
             замолчавшие узлы, записи по сроку; дальше сверка CDR, выплаты, ASR, MNP
  esl/     — потребитель событий FreeSWITCH (долгоживущее соединение)
  agent/   — агент узла, собирается в самодостаточный бинарник
packages/
  shared/  — типы, zod-схемы, доменные ошибки, работа с деньгами
  db/      — схема Drizzle и миграции
  config/  — модуль конфигурации (ADR-0002)
  logger/  — логгер (ADR-0004)
node/      — конфигурация FreeSWITCH и скрипт установки узла
android/   — приложение партнёра (Kotlin)
docs/      — документация (см. ниже)
scripts/   — check.sh: единая точка проверки проекта
.github/   — CI: те же проверки, но на Ubuntu
.claude/   — конфигурация Claude Code: settings.json, commands/, skills/
.mcp.json  — MCP-серверы проекта
.env.example — все переменные окружения, которые читает приложение
```
Доменные модули — в `apps/api/src/modules/`, поимённо совпадают с таблицей компонентов
в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

- `explore-area` — разведка незнакомой области кода перед правкой
- `vertical-slice` — новая фича сквозным срезом по образцу существующей
- `diagnose-flake` — разбор проверки, которая проходит не всегда: воспроизвести или
  исключить измерением, но не принять совпадение за причину
- `node-live` — проверка узла АТС на живой машине и запись выясненного: `scripts/node-config.mjs`
  видит только механическое, а «работает ли» отвечает лишь живой FreeSWITCH
- `ui-review` — проверка интерфейса кабинета: наши правила из DESIGN.md и зафиксированная
  копия правил Vercel, в коде и в браузере, включая ширину телефона. Гейт отвечает,
  оживает ли кабинет, а удобен ли он — только этот навык

MCP-серверы (`.mcp.json`), использовать по назначению:
- **context7** — актуальная документация библиотек. Обращаться к нему, а не полагаться
  на память, когда речь о конкретном API, версии или изменившемся интерфейсе.
- **playwright** — запуск браузера, E2E-сценарии, скриншоты.
- **chrome-devtools** — отладка фронтенда, сеть, профилирование производительности.
- **git** — операции с историей репозитория.
- **shadcn** — компоненты shadcn/ui для `apps/web`.
- **@21st-dev/magic** — генерация UI-компонентов React.

Ключи MCP лежат в `.claude/settings.local.json` (не в git). В `.mcp.json` — только ссылки
на переменные окружения. Не переносить ключи в файлы, попадающие в репозиторий.

## Правила работы

1. **Контекст перед действием.**
   Перед изменением кода — понять затрагиваемую область: архитектуру, связанные файлы,
   зависимости, существующие реализации. Уже прочитанное в этой сессии не перечитывать.

2. **Не плодить дубли.**
   Сначала искать существующее решение (поиск по домену и именам), потом писать новое.
   Расширить существующее лучше, чем создать параллельное. Следовать сложившимся паттернам
   проекта, даже если лично мне привычнее иначе.

3. **Спрашивать по порогу, а не по любому поводу.**
   Остановиться и спросить, если решение: необратимо; меняет архитектуру, схему БД или
   публичный контракт; либо варианты дают существенно разный результат.
   Мелкие развилки — решать самому и обозначить принятое допущение одной строкой.
   Если задача противоречит архитектуре или ранее принятому ADR — не реализовывать,
   сначала объяснить конфликт и предложить вариант.

4. **Production-ready, но без переусложнения.**
   Да: полная обработка ошибок, валидация входных данных, безопасность, масштабируемость,
   логирование, тесты на новое поведение.
   Нет: заглушки и «пока так», молчаливое проглатывание исключений, абстракции «на будущее»,
   слои ради слоёв. Правильное решение — самое простое из тех, что решают задачу полностью.

5. **Целевая ОС — Linux, всегда.**
   Разработка ведётся в WSL2 (Ubuntu 24.04), прод — Ubuntu. Код, скрипты и команды
   пишутся под Linux; Windows-специфичных путей и зависимостей быть не должно.
   Пути — только через API работы с путями. Имена файлов не различаются регистром
   (проверяется в CI). Переводы строк — LF (см. `.gitattributes`).
   Сборка, тесты и `scripts/check.sh` должны идти в WSL2, а не в оболочке Windows:
   проверка, прошедшая в другой ОС, мало говорит о той, где код будет работать.
   Фактически они пока гоняются в Windows — это открытый вопрос в [TASKS.md](TASKS.md),
   «Требует вашего решения». Пока он не закрыт, вместе с результатом проверки называется
   и оболочка, в которой она прошла.

6. **Проверка — это запуск, а не обещание.**
   По ходу работы допустимо гонять отдельные шаги — те, что относятся к правке. Но перед
   отчётом о готовности прогоняется полная проверка целиком, и её вывод показывается.
   Не заявлять «ошибок нет», если проверка не запускалась. Если запустить невозможно —
   сказать об этом прямо и перечислить, что осталось непроверенным: `НЕ ВЫПОЛНЕН` —
   это не «прошло».

7. **Отчёт после задачи** — кратко и по делу:
   что сделано → что проверено и как → что осталось / не доделано → найденные проблемы
   с указанием `файл:строка`.
   Побочные наблюдения — не больше 3–5 пунктов и только реальные проблемы в затронутом коде.
   Идеи новых фич — в [TASKS.md](TASKS.md), не в отчёт.
   Полный аудит проекта — отдельно, по команде `/audit`.

8. **Контекст обрывается без предупреждения.**
   Сессия может закончиться в любой момент, и всё, что я знаю только из разговора, исчезнет.
   Поэтому важное фиксируется в файлах **сразу, а не в конце**:
   - решение принято → ADR, до начала реализации;
   - выяснен факт о внешней системе, API, оборудовании, ограничении → в `docs/`;
   - задача разбита на шаги → шаги в [TASKS.md](TASKS.md), отмечать по мере выполнения;
   - работа прервана на середине → строка в TASKS.md о том, где остановились и почему.

   Проверка: «если сессия оборвётся прямо сейчас, сможет ли следующая продолжить с этого
   места по файлам?» Если нет — сначала записать, потом продолжать.

9. **Документация — часть задачи.**
   Изменилось поведение или контракт → обновить `docs/`.
   Принято архитектурное решение → новый ADR в [docs/adr/](docs/adr/).
   Появился незакрытый хвост → строка в [TASKS.md](TASKS.md), а не безымянный `TODO` в коде.

10. **Язык проекта — русский.**
    Документация, комментарии, сообщения коммитов, ADR и отчёты — по-русски.
    Английский — только там, где он часть машинного контракта: идентификаторы кода,
    имена файлов и веток, поля JSON, значения перечислений в БД, типы Conventional Commits.
    Доменный термин берётся из [GLOSSARY.md](docs/GLOSSARY.md) в его русской форме: единый язык
    кода и обсуждений — ради этого глоссарий и заведён.

11. **Новая зависимость — решение, а не мелочь.**
    Пакет берётся, когда своя реализация дороже сопровождения чужой. Ради одной функции
    или короткого списка констант зависимость не заводится. У каждой новой — строка
    обоснования в сообщении коммита; шаг «Аудит зависимостей» в проверке отвечает
    за уязвимости, а не за уместность.

12. **Правило, разошедшееся с кодом, — дефект.**
    Если правило описывает то, чего в проекте нет (несуществующая команда, «ловится
    линтером» без такого правила линтера), это надо сказать и предложить правку файла,
    а не молча исполнять или молча игнорировать. Правила описывают действующий проект,
    а не намерения.

Номера правил — адрес: на них ссылаются [`scripts/docs-links.mjs`](scripts/docs-links.mjs),
[ADR-0007](docs/adr/0007-lokalnaya-sreda.md) и навык `vertical-slice`. Новое правило
дописывается в конец, отменённое помечается, но номер не переиспользуется.

## Доменные правила, нарушение которых стоит денег

- **Деньги — только `bigint` в микроединицах** (1 руб = 1 000 000), тип `Money`
  из [packages/shared/src/money.ts](packages/shared/src/money.ts). Тип брендированный:
  подстановка обычного `bigint` или `number` — ошибка типов, а `strictTypeChecked`
  дополнительно не даёт смешивать `bigint` с `number` в арифметике. Отдельного правила
  линтера «`number` в деньгах» в проекте **нет** — держит типизация. Округление — только
  при фиксации денежной суммы ([ADR-0010](docs/adr/0010-model-billinga.md)), промежуточные
  вычисления остаются точными.
- **Миграция генерируется по собранной схеме.** `pnpm db:generate` читает `dist`
  ([ADR-0017](docs/adr/0017-sborka-paketov-monorepozitoriya.md)), поэтому изменение
  перечисления в `packages/shared` без `pnpm build` в миграцию не попадёт: таблица
  создастся, а ограничение `CHECK` останется прежним. Ловится шагом «Миграции» —
  но дешевле собрать сразу.
- **Схема БД меняется только миграцией** ([ADR-0005](docs/adr/0005-migracii.md)), а соглашения
  схемы заданы в [ADR-0016](docs/adr/0016-soglasheniya-shemy-bd.md): идентификатор — `uuid`
  без `DEFAULT`, перечисление — `text` с `CHECK` (не тип `enum`), время — только `timestamptz`.
  `drizzle-kit push` не используется никогда.
- **Применённая миграция не правится.** Расхождение с уже накатанной базой обнаружится
  на проде и будет инцидентом; исправление — только новая миграция. Разрушающее изменение
  (удаление или переименование колонки, сужение типа) делается в два шага с промежуточным
  состоянием, совместимым и со старым, и с новым кодом ([ADR-0005](docs/adr/0005-migracii.md)).
- **Баланс меняется только проводкой** в модуле `billing`. Прямая запись в остаток запрещена.
- **Модуль не ходит в чужие таблицы** — только через публичный интерфейс владеющего модуля,
  а к своим данным — через собственный репозиторий (раздел «Границы модулей»
  в [ARCHITECTURE.md](docs/ARCHITECTURE.md), «Структура модуля» в [CONVENTIONS.md](docs/CONVENTIONS.md)).
- **Оператор номера — только через `OperatorResolver`** ([ADR-0013](docs/adr/0013-opredelenie-operatora.md)).
  Определять по префиксу нельзя: из-за MNP это неверный оператор.
- **Вызов с неподтверждённым оператором не совершается вообще.** У всех партнёров тариф
  «безлимит внутри своей сети», запасных SIM с внесетевыми минутами нет. Верный оператор —
  звонок бесплатен, неверный — деньги партнёра. Промежуточного варианта не существует.
- **Канал с `recording_required` не маршрутизируется на шлюз типа `android`** —
  там запись технически невозможна ([ADR-0012](docs/adr/0012-mobilnoe-prilozhenie.md)).
- **Клиент никогда не видит, кто такой партнёр.** Только `PartnerAlias`. Имя, контакты,
  реквизиты, номера SIM, адреса шлюзов в клиентский контур не попадают ни в каком виде —
  ни в API, ни в отчётах, ни в CDR ([ADR-0014](docs/adr/0014-vybor-partnera-klientom.md)).
- **Клиент и его канал звонят только в состоянии `active`, оба.** Маршрутизация
  проверяет и канал, и владеющего им клиента: приостановленный клиент не звонит ни
  по одному каналу. Переводит человек через `PATCH /clients/:id/status`, `closed`
  необратимо ([DOMAIN.md](docs/DOMAIN.md), «Жизненные циклы»).
- **Партнёр работает только в состоянии `verified`.** И регистрация его шлюза,
  и отбор SIM под вызов требуют именно его; любое другое состояние означает «трафик
  не идёт». Переводит человек через `PATCH /partners/:id/status`, `closed` необратимо
  ([DOMAIN.md](docs/DOMAIN.md), «Жизненные циклы»).
- **Вызов уходит только на железо своего узла.** Отбор кандидатов сужается узлом,
  приславшим запрос: диалплан набирает шлюз как зарегистрированного пользователя,
  и с соседнего узла такой записи не существует. Шлюз без регистрации вовсе — не ёмкость.
  Отказ тогда называется `gateway_unregistered`, а не «нет SIM»: это разговор о железе.
- **Коридор — единственное ограничение на цену партнёра**
  ([ADR-0023](docs/adr/0023-koridory-cen.md)), и с тех пор как цену назначает сам партнёр,
  оно обязано быть непроницаемым. Три следствия, каждое проверено:
  проверка коридора и запись цены — **одна транзакция** с запиранием направлений
  оператора; **направление без коридора партнёру закрыто** (администратору нет — он
  коридор и задаёт); **момент начала действия у партнёра не принимается** — иначе он
  выберет время, когда коридор был шире. Сравнивается стоимость эталонного вызова,
  а не цена за минуту: коридор по одному числу из пяти обходится платой за соединение.
- **Цена решает порядок терминации** ([ADR-0040](docs/adr/0040-poryadok-terminacii-predlozhenie-i-cena.md)).
  Кандидаты перебираются так: приоритет предложения → цена по направлению → давность →
  номер SIM. Единица приоритета — **предложение**, партнёр вместе со способом терминации
  (`sim`/`sip`), а не партнёр целиком. Кандидат без действующей цены по направлению
  в перебор **не попадает вовсе**: тарифицировать его нечем, и отказ тогда называется
  `no_tariff`, а не «нет SIM».
- **Собственный контур не принимает идентификатор владельца** — он выводится из сессии
  (`BillingService.requireClientOwnedBy`, `requirePartnerOwnedBy`). Пути `/client/*`
  и `/partner/*` тем и отличаются от административных `/clients/:id/*`
  и `/partners/:id/*`, что подставить в них чужой идентификатор нечего. Учётная запись
  без привязанной записи получает `404`, а не пустой ответ: это незавершённое заведение,
  и «у вас ничего нет» было бы неправдой.
  Причина отказа уходит клиенту через `clientFailureReasonOf`: всё, что не про него
  самого, схлопывается в `platform` — по внутренним причинам читалась бы ёмкость
  площадки ([docs/api/client.md](docs/api/client.md)).
  Симметрия обоюдная: партнёр не видит клиента и его цену так же, как клиент не видит
  партнёра ([docs/api/partner.md](docs/api/partner.md)).
- **Доступ к обработчику закрыт по умолчанию** ([ADR-0018](docs/adr/0018-autentifikaciya.md)):
  защитник глобальный, открывается пометкой `@Public()`. Роль — только первый рубеж;
  владение конкретным объектом проверяет сервис.
- **Изменяющее обращение считается** ([ADR-0041](docs/adr/0041-predel-chastoty-izmeneniy.md)):
  второй глобальный защитник даёт учётной записи 120 изменений в минуту и отвечает `429`
  с заголовком `Retry-After`. Новый обработчик попадает под предел сам. Не считаются
  чтения, машинный контур (`@Machine()` — объём узла это телефония, и предел там означал бы
  несостоявшиеся звонки), публичные пути (у них свои пределы под свою угрозу) и дверь
  наружу — выход и закрытие сессии (`@Unmetered()`). Redis недоступен — обращение
  проходит: это предел объёма, а не рубеж доступа.
- **Поиск по части текста — только через `containsIgnoringCase`**
  ([ADR-0038](docs/adr/0038-poisk-bez-uchyota-registra.md)). В локали `C` PostgreSQL
  не приводит регистр кириллицы вовсе: `ilike` по названию находит «Такси» и не находит
  «такси», причём молча. Помощник задаёт локаль явно и экранирует знаки шаблона.
  Сортировка человекочитаемых названий — по той же причине через `orderByText`:
  иначе «Яндекс» встаёт раньше «абв».
- **Кабинет ходит в API только через `apps/web/src/lib/api.ts`**
  ([ADR-0037](docs/adr/0037-sessiya-v-brauzere.md)). Там ставится заголовок `X-Zvonix-Web`,
  без которого изменяющий запрос по cookie получает `403`. Свой `fetch` в обход — это
  запрос, который не пройдёт, и узнают об этом не на ревью.
- **Действие админа над деньгами, тарифами и лимитами журналируется** — состояние до
  и после, в модуле `audit`. Новый административный обработчик без записи в журнал
  считается недоделанным.
- **Номера абонентов и записи разговоров — персональные данные.** Номера маскируются в логах,
  записи — только в объектном хранилище с подписанными ссылками и аудитом обращений.
- **Тарификация идемпотентна по идентификатору вызова.** Повторный CDR не создаёт вторых
  проводок — узел может слать его повторно, это штатный режим.
- **Фоновая задача идемпотентна и догоняюща** ([ADR-0020](docs/adr/0020-fonovye-zadachi.md)):
  отбирает работу по сроку, а не «сделанное с прошлого запуска». Иначе пропущенный тик
  теряет работу навсегда, а два экземпляра воркера мешают друг другу.
- **Конфигурация приходит из окружения и проверяется при старте**
  ([ADR-0002](docs/adr/0002-konfiguraciya.md)). Новая переменная заводится одновременно
  в схеме конфигурации и в `.env.example`: расхождение ловит тест, но дописать строку
  сразу дешевле, чем чинить упавшую проверку.

## Никогда

- Не коммитить секреты, `.env`, ключи, дампы с реальными данными.
- Не менять схему БД и публичные контракты без ADR и подтверждения.
- Не глушить линтер и типы ради «чтобы прошло» (`type: ignore`, `eslint-disable`, `any`)
  без обоснования в комментарии рядом.
- Не делать `git push`, `git commit`, деплой и миграции на проде без явной просьбы.
- Не оставлять закомментированный «на всякий случай» код — для этого есть git.
- Не править сгенерированное и собранное: `dist/`, `packages/db/migrations/meta/`.
  Меняется источник, результат пересобирается. Единственное исключение — поле `tag`
  в `_journal.json` при переименовании миграции сразу после генерации
  ([ADR-0005](docs/adr/0005-migracii.md)); снимки схемы не трогаются.
- Не отмечать задачу в [TASKS.md](TASKS.md) выполненной, пока проверка на ней не прошла.
